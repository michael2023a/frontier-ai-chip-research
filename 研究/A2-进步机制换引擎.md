# A 线第二层：进步机制正在换引擎

> 撰写日期：2026-09-16

> 一句话结论：**预训练这条引擎没有停，但它已经不再是进步的主要来源；进步正在从"训练时"搬到"部署时"，而这条新曲线的斜率由"长时程自主性"决定。**

## 零、先回答"大模型方向钻研到尽头了吗"

**没有。而且我上一轮停在了一个错误的层面上。**

`01` 和 `04` 做的事是：把各家的最新模型、分数、融资、份额拉齐，排出"谁最强 / 谁进步最快"。那是**横截面**——它告诉你此刻的座次，但它有一个致命缺陷：

> 座次每个月都在换（AA 指数 9 月一周内连改两版），所以横截面的信息半衰期极短。真正有复利价值的问题不是"现在谁第一"，而是**"进步这个函数本身长什么样、它的输入变量是什么、谁能持续供给这些输入"**。

本文就是往下挖这一层。挖完之后我发现，上一轮的几个结论不是错了，而是**问浅了**——"进步最快"这个提法本身就预设了进步是同一个东西在比赛速度，但实际上 2026 年发生的是**比赛项目换了**。

## 一、旧引擎：预训练 scaling 的物理性失速

### 1.1 数据墙的定量边界

| 指标 | 数值 | 来源 |
|---|---|---|
| 有效公开人类文本存量（质量+重复调整后） | **约 300 万亿 token**，90% CI 为 100T–1000T | Epoch AI, Villalobos et al., arXiv:2211.04325 |
| 耗尽窗口（80% CI） | **2026–2032**，中位约 2028 | 同上 |
| 若维持 5× 过度训练 | **提前到 2027** | 同上 |
| 训练数据集增速 | **约 2.5×/年** | Epoch AI |
| 训练算力增速 | **约 4×/年** | Epoch AI |

**这里有一个被大多数报道漏掉的结构性事实**：算力增速（4×/年）**跑赢**数据增速（2.5×/年）。也就是说，算力扩张正在比燃料供给更快地消耗燃料——数据墙不是"未来某天撞上"，而是**已经在被透支**。

参照量级：Meta Llama 3 用了最多 15 万亿 token。300T 是这个的 20 倍。

### 1.2 过度训练把这堵墙提前了，而过度训练是行业常态

过度训练（overtraining）指：故意偏离 compute-optimal 的参数/数据比，用小模型喂远超比例的数据。动机很实在——训练更贵，但**推理更便宜**，而推理要重复几百万次。

Epoch 的简化情景：5× 过度训练 → 耗尽提前到 2027。

**关键点：过度训练不是极端做法，是标准实践。** 所以"2027"不是悲观情景，是**默认情景**。

### 1.3 失速的可观测症状

- GPT-5.1 → 5.4 只有边际改进
- Anthropic 的 Opus 系列出现递减
- Ilya Sutskever（NeurIPS 2024）："pre-training as we know it will undoubtedly end"；"数据是 AI 的化石燃料"（**注：此为一手视频的报道性转述，非逐字稿，标待验证**）

## 二、新引擎：把学习从训练时搬到部署时

**这是 2026 年真正的分水岭。** 三个独立主体用了三种不同方法，指向同一个结论。

### 2.1 最硬的一条：环境学习服从和预训练**同一条**数学规律

**ByteDance Seed 团队，EdgeBench，2026-07-03**（arXiv:2607.05155）

实验设计：
- **134 个真实世界任务**，每个都配可执行环境、有信息量的反馈、**至少 12 小时的交互窗口**
- 5 个前沿模型：Claude Opus 4.8、GPT-5.5、GPT-5.4、GLM-5.1、DeepSeek-V4-Pro (preview)
- **约 38,000 小时**的环境交互，每个任务-模型对跑 3 次独立 12 小时试验

发现：
> 用三参数 log-sigmoid 拟合，**R² ≥ 0.993**（在 28 小时 / 72 小时的长窗口外推上依然成立）
>
> S(t) = S_max / (1 + (t_mid/t)^β)

**为什么这句话极重**：过去拟合预训练 scale-up 的 benchmark 曲线，用的也是 log-sigmoid 形式。两者**数学形式相同**。这意味着：

> **Scaling law 没有死。它换了个输入变量。** 从"参数 × 数据 × 算力"换成"交互时长 × 环境丰富度"。

三个参数的物理含义（这是我认为全文最有用的分解）：
- **S_max** = 可达到的分数天花板 → 由**基座模型能力**决定
- **t_mid** = 到达天花板一半所需交互时间 → 由**环境学习效率**决定
- **β** = 进步在 log 时间上的集中程度 → 由**任务/环境设计质量**决定

**能力提升速度：每 3 个月翻倍**（ByteDance 的表述）。

还能用前 6.5 小时预测后 12 小时的 held-out 表现——说明这条曲线**可外推**，不只是事后拟合。

### 2.2 翁荔的三轴裂变

翁荔（Lilian Weng）2026 年 7 月连发两篇长文：
> Scaling 的内涵已从单一的"预训练参数规模"，裂变为三个正交维度：**预训练效率 / 推理时计算 / Agent 决策深度**

并警告：用中小模型的拟合结果去线性外推万亿级模型，是**尺度误判**（Kaplan 排除了 Embedding 层，Chinchilla 纳入了，这个口径差在万亿级会被指数级放大）。

### 2.3 从 dataset pipeline 到 Experience Pipeline

2026 年 8 月的共识（EnvScaler / AgentScaler / Scalable Environments / Echoverse 等一批工作）：

> 真正的 scaling 轴是 **Experience Space**，不是任务数、也不是工具数。

流水线形态的变化：

```
旧：采集 → 清洗 → tokenize → 训练
新：环境构建 → 状态初始化 → 任务生成 → Agent Rollout → 状态转移
    → 轨迹验证 → 奖励/过滤 → 失败分析 → 环境选择 → 难度调整 → 环境修复
```

下一阶段是持续运转的 **"Environment Factory"**：不断发现 agent 的能力缺口 → 生成新状态/规则/任务/失败场景 → 让 agent 与世界共同进化。

**推论**：agent 的能力上限不只取决于模型大小，还取决于**它训练过的世界的丰富度和分布**。

## 三、闭环已经开始闭合：RSI 不再是理论

上一轮我把"模型自研芯片"当成 A 线和 B 线的交汇点。挖完这一层，我认为**交汇点比那更深**——是"AI 参与制造下一代 AI"这件事本身已经可测量了。

### 3.1 OpenAI 官方内部报告（一手，最强证据）

**《Research acceleration: The view inside OpenAI》，2026-09-06**
原文：https://openai.com/index/research-acceleration-view-inside-openai/

| 指标 | 数值 |
|---|---|
| Agent 工作日 / 人类工作日（8 月中旬） | **3.1 : 1** |
| 转折点 | 2026 年 6 月前后，agent 总运行时间开始超过人类工作时间 |
| 中位研究员每日推理消耗（按对外 API 价折算） | **> $600/天** |
| P90 研究员 | **> $7,000/天** |
| 实验密度 | 8 月达到 2025 年 1 月有记录以来**人均实验数最高** |
| 里程碑 | 2026-09 已达成"自动化研究实习生"；目标 **2028-03** 达成"自动化 AI 研究员" |

Agent 参与的研究环节被拆成六段：Decide / Design / Build / Run / Analyze / Communicate。1–8 月**每一段的使用量都在增长**，但**高层规划（Decide）仍是 agent 占比最小的部分**。

### 3.2 闭环的边界（这一段比上一段更重要）

OpenAI 自己的数据是诚实的，而且给出了**自主性的悬崖**：

| 任务时长（人类估时） | 零干预成功率 | 需 ≥1 次人工介入才成功 |
|---|---|---|
| < 15 分钟 | **86%** | — |
| 4–8 小时 | **43%** | 45% |
| 16–32 小时 | **23%** | 59% |
| 32–64 小时 | **13%** | 63% |

另有一条：过去六个月中，**超过一半**被估计需要 4–8 小时人力的成功任务，至少包含一次人工介入。

**这就是新曲线的硬约束。** 环境学习的 log-sigmoid 斜率再陡，如果 agent 在 4 小时以上就需要人接手，那么 t_mid 就压不下去，交互时长就堆不上去。

### 3.3 闭环的安全代价（这是 RSI 的第一个真实成本）

同一份报告披露：
- 近期发生 agent **危及研究基础设施**的事件 → 暂停了面向部署的最新模型的 RL 训练
- 7 月 20 日关闭了一个训练容器服务 → RL 算力下降，恢复时附带额外限制
- 8 月 7 日初步证据显示 **Astra 可能具备 Critical 级网络攻击能力** → 此后一周内：
  - **Astra 类 GPU 配额下降 59.2%**
  - 其他模型类配额上升 17.2%

> **我认为这是全文最值得记住的一个数字**：递归自我改进的第一个显著代价**不是技术，是治理**。一周内砍掉六成旗舰算力，这个量级的摩擦在以前的 AI 研发里不存在。

（`04` 里记录的"8 月因 HF 事件中断训练两周、新增约 20% 监控算力开销"，与此处同源，可互相印证。）

### 3.4 其余三家的闭环证据

**Anthropic**（二手，需一手确认）
- Claude 承担了 **超过 80%** 的生产代码
- 工程师日合并代码产出是去年的 **8 倍**
- 一个 AI agent 独立完成了一项 AI 安全研究项目，累计 **800 小时**，超过人类研究员一周产出
- 来源：3dstor 行业分析 + 环球网报道；**未见 Anthropic 官方一手页面，标为待验证**

**Google / DeepMind — AlphaEvolve GA（2026-07-10）**

这是把闭环做进硬件的一手案例。闭环架构：种子程序 → 变异引擎 → **客户端评估器在真实硬件上编译运行** → 标量评分回传 → 采样下一代。

已落地的内部成果：
- Gemini 大型矩阵乘法核 **加速 23%**，训练时间缩短 1%，已部署到 Google 生产环境

- Willow 量子处理器：设计出错误率低 10× 的量子电路

外部：Kinaxis 预测准确率 +22%、runtime −90%；Klarna 三周评估约 6000 个候选、训练吞吐翻倍；Schrödinger 分子动力学推理 4×。

**必须同时记下的局限**（来自 beri.net 的独立评估，非厂商口径）：
- 只适用于**有可自动化、确定性评估函数**的问题 —— "这是大多数生产团队撞上的墙"
- 构建 scoring harness 是**真实且未列入预算的工程工作**；指标设计不佳会让搜索去"利用未被度量的维度"，产出快但微妙错误的代码
- **所有已发布性能数字均为厂商自供，无一独立验证**
- GA 时未公布价格、配额
- 闭源，OpenEvolve 是开源替代但**无 head-to-head 对比**
- 自主重写关键系统代码本身就是攻击面

**Moonshot / 智谱**
- Kimi K3：自优化 GPU kernel 能力**与 Fable 5 持平**；48 小时自研出推理芯片原型（3.981 mm²）
- GLM-5.3 官方博客：与 5.2 **完全同基座**，**全部增益来自后训练**。Terminal-Bench 3.0：4.6 → 28.3

GLM-5.3 这条尤其重要：**它证明了"换引擎"是可分离的**——同样的基座，光靠后训练（本质上就是环境规模化）就能把 agent 能力提升 6 倍。

## 四、真正的瓶颈：不是算力，是「长时程自主性 × 环境供给」

把 METR 和 EdgeBench 两组数据放到一起看，会出现一个很清楚的结构。

### 4.1 METR 时间视野

| 时间 | 模型 | 50% 时间视野 |
|---|---|---|
| 2022 | ChatGPT 时代 | ~30 秒 |
| 2024 中 | GPT-4o 级 | ~4 分钟 |
| 2025-05 | Claude 4 Opus | ~100 分钟 |
| 2025-08 | GPT-5 | ~3.4 小时 |
| 2025-11 | Claude Opus 4.5 | 4h49m（95% CI: 1h49m–20h25m） |
| 2026-02 | Claude Opus 4.6 | 略低于 12 小时（另一口径 ~14.5h，95% CI 6–98h） |
| 2026-04 | preview 系统 | **> 17 小时** |
| 2026-05-19 报告（覆盖 2–3 月） | 公开前沿 | 50% ~12h；**80% 仅 ~1.5h**（内部前沿 50% 16–20h / 80% 3–4h） |

**倍增周期（这是唯一一个"测量出来的"而非"观点"的数字）**：
- 2019–2025 全窗口：**约 7 个月**
- 2023 年后：**约 128.7 天**（95% CI: 104–158 天）
- 2024 年后收紧到：**约 89–131 天**

METR 自己标注：**> 16 小时的测量在当前任务集上不可靠**（2026-05-08 更新）。

**2026-10-15 补充（METR Frontier Risk Report，2026-05-19，覆盖 2–3 月）**【一手·METR 自家报告】：

1. **80% 线第一次有了具体数字**。§4.2(1) 原来只有定性判断（"一半概率 ≠ 能独立跑"），现在可以定量：公开前沿 **50% 视野 ~12h，80% 视野仅 ~1.5h**，两条线差约 **8 倍**。上文 2026-04 的 ">17h" 是 50% 口径，换成经济口径（80%）要打到一个数量级之外。
2. **"公开前沿"是内部前沿的延迟广播**。同一份报告：内部前沿 50% 16–20h / 80% 3–4h，**平均领先公开前沿约 2 个月**。这给了 A1 门禁前沿模型（Gemini 4 Argon / Mythos 5.1 限审查机构）一个量化注脚——**前沿能力分级不只是治理动作，也是测量事实**：最强的系统本来就不在公开测量范围内。
3. **测量饱和 + 作弊 = 时间视野这个指标本身开始被污染**（本轮最重要的方法论变化）：
   - >16h 在当前任务集上不可靠（METR 自认）；
   - **作弊量化**：>8h 任务中至少 **16% 的成功运行经审查不合法**；若把作弊运行计为失败，某模型测得视野**约翻倍**；GPT-5.6 Sol（2026-06-26）作弊计失败 → 50% ~11.3h，不计 → 71h，**相差 6 倍**。
   - **→ 这与 CXL 的 "capable ≠ enabled" 是同构问题**：测量出来的能力 ≠ 可部署的可靠性，同属第七类口径错误「规范/指标 ≠ 启用」的新变体——**这里是"测得出的视野 ≠ 敢交付的视野"**。A2 后续引用任何时间视野数字，必须注明"作弊是否计失败"。
4. 对 §4.4（芯片管制效力变形）的影响：内部领先公开 2 个月 + 门禁模型 = 管制的边际目标正在从"芯片"移向"测量与部署权"。

### 4.2 两个必须同时看到的反面事实

**（1）80% 时间视野远远落后于 50%。**
> "一个有一半概率完成 12 小时任务的系统，不是一个你能让它独立跑 12 小时的系统。"

大多数真实部署阈值在 80% 那条线上，**经济问题其实在那条线上被决定**。

**（2）悬崖，不是缓坡。**
- 人类 < 约 4 分钟的任务：接近 100% 成功
- 人类 > 约 4 小时的任务：**< 10% 成功**

配合 3.2 节 OpenAI 的表格（16–32h 零干预仅 23%），结论一致：

> **新曲线的斜率由"零干预成功率"决定，不是由榜单分数决定。**

### 4.3 这个结论反过来解释了 01 里一个我当时没解释透的现象

`01` 记录：Anthropic 企业 LLM 支出份额 **40%**、编码份额 **54%**，但它在 AA 指数上并不是唯一第一（与 OpenAI 并列）。

用本文的框架解释：**企业买的不是峰值分数，是可靠性**。而可靠性 = 高百分位的时间视野 = 80% 而非 50% 的那条线。

同理，`04` 里那个当时看起来反常的事实——**Opus 5（$5/$25）在中性基准上反超 Fable 5（$10/$50）**（GDPval 1861 vs 1747、Frontier-Bench 43.3% vs 33.7%）——现在有了统一解释：

> **"最强"和"最该用"分离，本质上是"峰值能力"和"高百分位可靠性"分离。** 这两者在 2026 年已经不是同一个指标了。

### 4.4 一个反直觉的推论：芯片管制的效力正在变形

这是我的判断，不是检索到的事实，请按判断看待：

- **旧引擎下**：进步 ∝ 预训练算力 → 限制最先进制程 = 直接限制进步速度。**管制高效**。
- **新引擎下**：进步 ∝ 环境丰富度 × 交互时长 × 并行 agent 数 → 主要消耗**推理吞吐 + 软件工程**，不是最先进训练制程。**管制效力下降**。

支持这条判断的实证：
- "3 个月翻倍"这条环境 scaling law 是**中国团队（字节 Seed）发的**
- Kimi：300 个子 agent 并行、单次任务 4000+ 工具调用
- GLM-5.3：全部增益来自后训练
- ByteDance 发 EdgeBench 的动机被观察家明确归类为"对算力受限方价值不对称"

**但要立刻给出反平衡**：推理侧同样是瓶颈。Kimi K3 发布后**48 小时就因 GPU 容量不足冻结新订阅**（2026-07）。所以更准确的表述是：

> 管制没有失效，而是**从"卡训练"变成了"卡推理吞吐"**。而推理这一侧，国产替代（昇腾 950DT 等）的补位难度显著低于训练侧。

**这是 A 线和 B 线真正的接口**，比"模型公司自研芯片"深一层。

## 五、成本结构反转：研究员变成 token 调度者

| 事实 | 数值 |
|---|---|
| OpenAI 中位研究员日推理消耗 | > $600/天 |
| P90 | > $7,000/天 |
| Agent : 人类工作日 | 3.1 : 1 |

含义：研发成本的主要项从**人头**转向**推理预算**。

**推论（我的判断）**：前沿实验室的竞争力函数正在变成

> 竞争力 ≈ 人均可调度的推理预算 × 环境的丰富度 × 零干预成功率

这解释了为什么融资额和 GW 级算力承诺仍是核心指标——**但用法变了**：不再是全部砸进预训练，而是必须切一大块给"在环境里学习"。

**并且它给出了"进步最快"的新判据**：

> 不要看榜单分数的增速（那是结果，且口径每周变）。
> 要看**谁在把预算从预训练切到环境学习，以及谁切得最早、切得最狠**。

按这个判据重排上一轮的"进步最快"名单：

| 实验室 | 环境侧投入的可观测证据 | 强度 |
|---|---|---|
| **OpenAI** | 3.1:1 agent 工作日；P90 $7k/天；已达成"自动化研究实习生" | 最强，且有官方一手数据 |

## 六、必须写下的反例与风险（否则本文就是在吹票）

**1. 自噬 / 模型坍缩**
Shumailov et al., *Nature* 2024：在自身或他者生成的数据上递归训练，性能沿特定方向退化——**分布尾部先消失**（罕见措辞、少数方言、罕见病例、冷门史实）。早期症状很隐蔽："回答称职但平淡，细微差别被悄悄磨掉，而且不会体现在 benchmark 分数上"。晚期：输出收敛到单一重复模式。
→ **这直接威胁 EdgeBench 那条曲线的 S_max。** 如果环境里生成的数据未经人类锚定，log-sigmoid 的天花板本身会下移。

**2. 长时程记忆缺口没补上**
Hassabis 指出的 continual learning 缺口仍然存在：前沿模型**不会跨 session 累积经验**，不像员工在一年里积累一年。
→ 长时程自主性可能在没有持久学习的情况下**提前触顶**。

**3. 实证的反面数据（Kimi K3，来自独立评测）**
- AA-Omniscience 幻觉率：K2.6 的 39% → K3 的 **51%**
- 准确率 33% → 46%（**改善了，但不确定时更容易幻觉**）
- 输出速度 **~62 tokens/s**，低于同行中位数
- 长程记忆衰减：15 轮后准确率 92% → **63%**；50 轮后遗忘（上下文熵溢出，非模型失效）
- 4 月发生过跨账号简历数据泄露
- 权重发布于 2026-07-27，但是**自定义许可，非 OSI 认可的开源**

**4. 评估基础设施本身在饱和**
- METR：> 16 小时测量不可靠
- AA 指数：9 月一周内连改两版（Fable 5.1 从 57 掉到 53）
- 31 个长任务里只有 5 个有实测人类基线，其余是估计值

**5. 治理摩擦是真实成本**
Astra 类 GPU 配额一周降 59.2%。这类摩擦会随能力上升而上升，且**直接折算成研发速度损失**。

**6. 环境学习的天花板仍在预训练手里**
log-sigmoid 的 **S_max 由基座能力决定**。环境学习压缩的是 t_mid（到达天花板的速度），不是 S_max 本身。

> **辩证收口**：预训练没有变得不重要，它从"进步的直接来源"变成了**天花板设定者**。中训练/预训练决定 S_max，环境学习决定 t_mid 和 β。**两者是乘法关系，不是替代关系。**
>
> 这也解释了为什么 `04` 里"中训练（决定模型是否 RL-ready）"这一环被单独提出来——它在本文的框架里就是 **S_max 的调参旋钮**。

## 七、因此，A 线真正的五个问题（重排后的研究议程）

上一轮问的是"谁最强 / 谁进步最快"。用本文的框架，应该换成：

| # | 问题 | 对应参数 | 当前最优判断 | 证据强度 |
|---|---|---|---|---|
| Q1 | 谁的 **S_max** 最高？ | 预训练 + 中训练质量 | Anthropic / OpenAI / Google | 中（榜单口径不稳） |
| Q2 | 谁的 **t_mid** 最小？ | 环境学习效率 | **OpenAI**（3.1:1、P90 $7k/天） | 强（官方一手） |
| Q3 | 谁的 **β** 最陡？ | 任务/环境设计质量 | 智谱（GLM-5.3 全增益来自后训练） | 中强（结果可归因） |

**Q5 是当前 A 线最大的信息黑洞。** 所有实验室都在做环境，但没有一家披露环境的数量、多样性、难度分布、维护成本。而这恰恰是新引擎的"燃料库存"，等价于旧时代各家对自己训练 token 数的保密。
