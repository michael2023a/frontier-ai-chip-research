## 〇、怎么用这份总纲

本课题最初按**两条线**组织：A = 谁在做模型、怎么做得更快；B = 支撑它们的硅和电，按产业层分工。**这个拆法是对的**（分析单位不同：A 是公司/实验室，B 是层），全部做完后也没有失效。

但做到最后一层（`AB-交汇·模型与硅.md`）时出现了一个此前没被写下的事实：

> **三条线各自独立推进，最后收敛到了同一组分母。**

三个例子说明这件事——也说明为什么现在需要一个结算框架：

| 三条线各自说的话 | 其实是同一个变量 |
|---|---|
| `A1b`：中国厂商的低价约 50% 工程效率 + 50% 战略补贴 | **`AB`：工程效率那一半主要是软件栈与利用率，不是硅** |
| `B7`：国产替代份额 90%，但有效算力产出仅海外 55–65% | **`AB`：同模型同硅，MTP 开关造成 21× 成本差** |

**→ 如果只按线组织，这三个结论会分别躺在三个文件里，互不照面。结算框架的作用就是让它们照面。**

## 一、★ 结算框架：三条线的七个共享变量

### 1.1 一句话版本

> **这个行业最终只结算一个数：每兆瓦能产出多少 token。**
> 三条线的所有争论——谁的模型强、谁的芯片快、瓶颈在哪一层——**最终都要换算到这个分母上才有意义。**
> 而决定这个数的，是七个变量。**七个变量里有四个不是芯片决定的。**

### 1.2 七个共享变量表

| # | 变量 | 定义 | A 线（模型）怎么看 | A-2 线（进步机制）怎么看 | B 线（芯片产业层）怎么看 | 主要观测源 |
|---|---|---|---|---|---|---|
| **1** | **每兆瓦 token 数** | 单位功率的产出 | 定价与毛利的真正分母 | 交互吞吐 = 新引擎的燃料 | 硅/电力/散热/互连的最终结算口径 | `AB` §6、`B4`、`B2` TCO |
| **2** | **利用率** | 买了的算力里真正跑起来的比例 | 服务成本（空转 = 纯亏） | — | **国产替代真伪的唯一硬指标** | `B7` §0、`AB` §6 |
| **3** | **KV / 内存需求** | 每 token 要搬多少字节 | MLA、MTP、压缩注意力直接改它 | 长上下文即燃料，越用越吃内存 | B3 的 HBM 需求侧；B6 的无 HBM 路线；**C1 的三条解耦路线都在争这个落点** | `B3` §5.1.2、`AB` §3、**`C1`** |
| **4** | **元数据访存占比** | 缩放因子/路由索引/压缩块索引在总访存中的比例 | FP4 / CSA / HCA 的副作用 | — | 近存与存算一体的新题；**随架构演进而上升** | `AB` §3.2（中兴 2026-04） |
| **5** | **域大小** | 一次并行能覆盖多少芯片、KV 能否留在域内 | 上下文长度与批规模 | — | **分界线：铜 vs 光、解耦 vs 统一池、CXL vs NVLink/CMX** | `B5`、`B8` §8.5.1、**`C1` §5.3 / §8.2** |

| **7** | **设计周期** | 从架构到可用硅的时间 | 模型迭代约 3 个月 | 闭环压缩周期 | **18–24 个月 → 9 个月（被 AI 压缩）** | `AB` §2.1、`B6` |

**★ 关键判读：七个变量里，只有 1（每兆瓦 token）、5（域大小）的一半、7（设计周期）主要由硅决定；2、3、4、6 主要由软件与架构决定。**
→ **这就是为什么本课题在 B 线（芯片）里反复得出"软件栈才是咽喉"的结论，且这个结论被 A 线独立验证。**

### 1.3 三个结算公式

**公式一 · 有效算力（判断"替代/份额"类数字的校准器）**
```
有效算力 ≈ 出货量（或名义算力）× 效率比 × 利用率
```
- 效率比：国产全链路 vs 海外 = **55–65%**（`B7`）
- 利用率：国产集群 **20–50%**，头部调优后 **80–90%**；NVIDIA 机柜出租率 **90%+** vs 国产 **<50%**（`B7`）
- **出处**：`B7` §6.3 ｜ **对应第五类口径错误「份额 ≠ 有效算力」**

**公式二 · 每 token 成本（乘法叠加，不是加法）**
```
每 token 成本 = f(硅代际) × f(软件栈) × f(模型架构) × f(利用率) × f(电价)
```
| 因子 | 量级 | 出处 |
|---|---|---|
| 硅代际（GB200→GB300） | **−57%** | `AB`（InferenceX） |
| **软件栈（MTP 开关）** | **21×** | `AB`（InferenceX，GB300 跑 DeepSeek R1：$2.35 → $0.11） |
| 软件栈（量化） | 约 5× | `AB`（B200 FP4+spot $0.047 vs H100 FP8 随需 $0.227） |
| 软件栈（连续批处理） | 2–4× | `B8` |
| 软件栈（提示缓存） | agent 负载 −45~80% | `AB` |
| 模型架构（MoE / MLA） | 显著 / KV −4–6× | `AB` §3.1 |
| 利用率 | 22%→68% 案例约 2.4× | `AB`（Spheron） |
| 电价 | 全生命周期 **60–70%** 运营成本 | `B4` |

**→ 历史对照：2023 初 GPT-4 水平约 $20/百万 token → 2026 约 $0.4（50×），就是这个乘法叠出来的。**

**公式三 · 最终结算口径**
```
利润率 ∝ tokens per megawatt（不是峰值 FLOPs）
```
**"峰值 FLOPs 从未改变。账单变了。"**（`AB` §6）

### 1.4 七个变量的因果链（★ 读框架时沿着这条链走）

```
   模型架构选择（MLA / MTP / FP4 / MoE）
        │
        ├──→ ③ KV 与内存需求 ↓        ──┐
        └──→ ④ 元数据访存占比 ↑        ──┤
                                        ├→ ① 每兆瓦 token 数
   软件栈（引擎/编排/传输/缓存）        │
        │                              │
        ├──→ ② 利用率 ↑                ──┤
        └──→ ⑤ 域大小要求（KV 能否留在域内）─┘
                    │
                    ├──→ 铜 vs 光（B5 的分界线）
                    └──→ 解耦 vs 统一池（B8 的第五个条件）

   ⑥ 编译器中间层 ──→ 决定硬件是否可替换 ──→ 决定谁能进这个市场
   ⑦ 设计周期 ──────→ 决定代差能否被追赶 ──→ 决定管制/护城河的有效期
```

**★ 这条链上最重要的两个"反直觉"节点**：
1. **③ 与 ④ 是反向的**：模型架构压低了 KV（③↓），却抬高了元数据（④↑）。**→ 内存墙没有被消除，只是被挪了位置。**（中兴 2026-04）
2. **⑤ 决定了一个"最佳实践"是否成立**：域够大（KV 常驻）→ 统一池更优；域小（KV 要跨机架搬）→ 解耦才划算。**→ `B8` 的解耦结论与 OpenAI 的反例不是矛盾，是同一个函数的两段。**

### 1.5 使用这个框架的三条纪律

1. **看到任何"份额/出货/替代率"数字，先过公式一。** 只说明"买了什么"，不说明"用出了什么"。
2. **看到任何"性能提升 X%"数字，先问它落在哪一栏。** 模拟 / 单卡微基准 / 厂商自报 / 真实生产流量 —— **跨栏换算一律不做，只并列。**
3. **看到任何"瓶颈"判断，先问它在七个变量里的哪一个。** 很多看似矛盾的结论其实在不同变量上（例：DeepGEMM 99.8% 说的是变量⑥的算子层，55–65% 说的是变量②和③的合成结果）。

| 口径 | 定义 | 当前值 | 来源 |
|---|---|---|---|
| ① **上架率** | 已上架机柜/服务器占比 | **71.4%** | 【官方】工信部 2026-06 |
| ② **卡时使用率** | 实际用算量 ÷ 供应量 | **36.8%**（38 亿卡时供应 / 14.07 亿卡时实际） | 【一手三方】信通院 2025 |

**→ 这是 `C1`「规范 ≠ 启用」的中国版本：「上架 ≠ 在用」。加上 `B7` 的「份额 ≠ 有效算力」，三者是同一类错误的三个实例——都是"把到位当成生效"（规范到位、机柜到位、份额到位，但产出没到位）。**
**→ 其他关键数字**：盈亏平衡线 = **四成上架率**；**全国仅 7 省智算中心上架率超 75%**，中西部与东北仅 **34–41%**，三四线城市空置率 **超 70%**；国产芯片集群业内估算闲置率 **70–80%**。
**→ ★ 需求侧对照排除了解释**：日均 token 调用量 **2024 初约 1,000 亿 → 2026-03 底 140 万亿（两年超千倍）**，同期智能算力 **+177%**，而利用率停在约 30% 不动。**问题不在需求不足，在结构错配**（运营主体：地方国资广泛空置；集群规模：千卡级达不到万卡门槛；**芯片代际：老卡 64 GB 显存 → 新卡 144 GB 后利用率飙升**）。
**→ 已固化为第五类口径错误「份额 ≠ 有效算力」。**

| **★ NVIDIA 叫 G3.5、华为叫 L3.5——两个互不通气的团队用了同一个层号** | `C1` §6.2 |
| 华为 OceanStor M900：基于灵衢、支持"一跳直连"的 **L3.5 层 PB 级 KV 缓存集群**；混合介质 + Retention 算法使 SSD 寿命 ×16 | `C1`（华为全联接 2026） |
| 阿里云"玄武"超节点：单柜 128 卡，背后接"内存柜"，通过 CXL 3.1 扩展 **PB 级共享内存池**；卡间访存延迟亚微秒级 | `C1`（ODCC 2026-01） |
| **行业共识分层：HBM（热）+ 本地 DDR5（温）+ CXL 池（大容量）——协同而非替代，"CXL 替代 HBM" 不成立** | `C1` §4.3 |
| **CXL 带宽 512 GB/s vs UALink 800 GB/s vs NVLink 5 1,800 GB/s——不是一个量级**；CXL 的优势是延迟低（200–500 ns）、一致性、可池化 | `C1` §4.3 |
| **★ 最轻的一栏（8B + 4K + 单轮 decode）实测 KV 全放 CXL 与放 DDR5 吞吐完全一致（Δ≤0.5%）** | `C1`（R/W Cache，ACM Turing China 2026，真实 CXL 测试台） |

**⚠ 冲突/修正**：`B6` 判定"绕开 HBM = 可得性优势"，但**这条优势有有效期**——`B8` 的软件若普遍削减 HBM 需求，相对优势被稀释（`B6` §6.1）。
**⚠ `C1` 追加的第二重修正**：即便 HBM 被绕开，KV 的容量压力也不会消失——它会落到一个**新的中间层**（G3.5/L3.5），而这个层的介质是 **DDR/flash，不是 HBM**。**"绕开 HBM" 在 2026 已经部分成真，但代价是系统里多了一层。**

### 变量 4 · 元数据访存占比（★ 本课题新提出的观察变量）

| 发现 | 出处 |
|---|---|
| **★ 瓶颈不是被消除而是被分化**：DeepSeek-V4 的 CSA+HCA+MTP 把原始 KV 换成压缩块，**降低原生 KV 容量但引入压缩索引/块元数据/稀疏检索新开销** | `AB`（中兴 2026-04 论文） |
| **FP4 混合量化成权重部署主流，group-wise 缩放因子与路由索引的元数据访存占比持续抬升** | `AB`（同上） |
| 三条新硬件需求：① 兼容"稠密潜变量 + 稀疏压缩块"两套缓存访问范式 ② 原生支持 Scale 元数据并行加载与快速解包 ③ MTP 改变算子调用模式，固定流水线近存硬件易降利用率 | `AB`（同上） |
| **★ 核心结论**："存算瓶颈正从传统 MHA 注意力层，迁移到 **MLA 潜变量缓存 + 压缩长上下文 KV 块访问 + MoE 专家权重访问**共同主导的新格局" | `AB`（同上） |
| 现存短板：软件栈与编译器支持不足、低精度量化误差控制、MoE 路由预测不确定性、**压缩注意力索引检索的硬件加速缺失** | `AB`（同上） |

**→ 这条对全课题的意义**：`B6` 说"绕开 HBM"、`B3` 说"HBM 是硬上限"。**本变量说明：即便 HBM 被绕开，瓶颈也不会消失，只会迁移到一个目前硬件加速缺失的环节。**
**→ "绕开 HBM" ≠ "绕开内存墙"。**
**→ 建议单列为观察线**（同时影响 B3 的 HBM 需求、B6 的近存/存算一体、B7 的 RRAM 路径）。

**★ `C3` 补充：这个变量终于有量化数据了，且定义被修正（`C3` §2 / §3）**

| 发现 | 数值/内容 | 出处 |
|---|---|---|
| **★ 首个量化基准：MXFP4 元数据占比** | 32 值块 = 16 B payload + 1 B E8M0 scale = **0.53125 B/value** → **元数据占总字节 1/17 ≈ 5.88%**（相对 payload +6.25%）；实际压缩率约 **3.0×** 而非干净 4× | `C3`（AMD MI355X/ATOM 部署文档，gfx950） |
| **★ 元数据是控制信息，不是数据** | **MoE 路由索引只有约 2 MB，却决定 All-to-All 通信模式，而 All-to-All 消耗总运行时间的 40–50%**；通信缓冲区峰值 1.2 GB | `C3` §3.1 |
| **★ 变量 4 的定义修正** | 必须按两层衡量：**L1 字节占比 + L2 撬动量**。只测 L1 会得出"元数据不重要"的错误结论（2 MB 撬动 40–50% 运行时间） | `C3` §3 |
| **元数据代价取决于硬件** | gfx950 上 block scale 是 **scaled MFMA 指令操作数流的一部分**（顺路带上）；不支持的硬件上是**额外一趟访存** | `C3` §2.1 |
| **★ 上升机制五环** | 注意力压缩 m=4→m'=128 ／ Lightning Indexer FP4 化 ／ **HCA token 强制 4 bit（已退化为纯元数据）** ／ KV 混合存储格式（RoPE BF16 + 其余 FP8）／ 权重 FP4 化 | `C3` §4 |
| **★★ HBM 正在从"数据层"变成"索引层"** | DeepSeek V4-Pro（1.6T MoE）1M 上下文仅需 **5.48 GB HBM**（GLM5 60 GB / Qwen3-235B 89 GB / GPT-5.5 级 180+ GB）；**Keys（压缩索引）留 HBM，Values 卸载到系统内存/SSD** | `C3` §5 |
| 硬件响应与缺口不在同一层 | 昇腾 950PR 做的是**数值格式**硬件加速（MXFP8/MXFP4 原生支持 + 融合 kernel）；中兴论文指的是**压缩注意力索引检索**的硬件加速缺失——**后者无人做** | `C3` §6.2 |
| 精度↔元数据↔开销↔面积 的兑换曲线 | NVFP4 块更小 scale 更精细（精度好、元数据多）；MXFP4 **tensor core 面积省 12%**；Meta 的 OAS+MBS 把 MXFP4/NVFP4 精度差从 10% 压到 <1%，代价 **GEMM +6.2%** | `C3` §6.3 |

**→ 对 `B3` 的修正**：HBM 需求模型要加**"单位 HBM 承载的 token 数"**，而不只看容量——HBM 里装的东西正在从"数据"变成"索引"。
**→ 与 `C1` 完美衔接**：C1 的三条路线把 KV 搬到 G3.5/L3.5 中间层，C3 说明 HBM 里留下的是索引。**两条独立路径指向同一结构。**

### 变量 5 · 域大小（★ 它决定了三个看似无关的结论）

| 发现 | 出处 |
|---|---|
| **分界线是域大小，不是技术偏好**：NVL72/144 用铜，NVL1152 跨机架才转 CPO | `B5` |
| 铜的物理极限：200 Gbps/lane 下无源铜 reach **约 1 米**；铜每比特比光便宜 **5–10 倍** | `B5` |
| **"光进铜退"是被市场误造的叙事**，黄仁勋 GTC 2026 亲自纠正："我们需要更多铜缆、更多光模块、更多 CPO 产能" | `B5` |
| **Google OCS 才是真正绕开 scale-up 护城河的**：Ironwood 9,216 芯片 3D Torus、1.77 PB 全局共享 HBM | `B5` |
| **★ 解耦 vs 统一池 = 域大小的函数**：域够大且 KV 常驻 → 统一池更优 | `B8` §8.5.1（`AB` 提出的修正） |
| **OpenAI 在 Jalapeño 上不做 PDD**："整颗芯片可能仅仅因为属于错误的池而闲置；局部利用率看起来更好，全局利用率可能很差"，且解耦破坏局部性 | `AB` |
| Jalapeño 局部域：128 XPU + 27.5 TB HBM4，6,144 对差分无源铜背板，每 XPU 单向 4.8 Tb/s | `AB` |
| NVLink Fusion 三条限制（含"每个部署必须至少含一件 NVIDIA 产品"）——**护城河四条落点里唯一写进合同的一条** | `B5` → `B1` |
| **★ NVIDIA 同时站在 CXL 的两侧**：CXL 联盟主席 Derek Rohde 是 NVIDIA 首席工程师；NVLink-C2C 官方支持 CXL 协议；Vera 支持 CXL 3.1；2025-09 收购 Enfabrica——**但域内用 NVLink 6 + CMX（以太网+flash），不用 CXL** | `C1` §5.3 |
| **判读：NVIDIA 不反对 CXL 作为域外/CPU 侧的内存扩展标准，但拒绝它成为 scale-up 域内的内存层** | `C1` §5.3 |
| **CXL 池化是解耦之争的第三方答案**：浪潮 MantaKV 把 P 节点 KV 集中写进 CXL 池化共享内存，D 节点直接读，**两次搬运合并为单次写入** | `C1` §8.2 |
| **但它没取消这条分界线，只是往外推了一格**：CXL 池化的域 = 柜级；跨机架要走网络，届时又回到解耦 | `C1` §8.2 |

**→ 这是本框架里"一个变量解释多个矛盾"的最佳例子**：铜/光之争、解耦之争、超节点规模之争，本质都是同一个变量。
**→ `C1` 追加第四个：CXL 之争。** NVIDIA 一边当 CXL 联盟主席、一边在域内不用 CXL，看似矛盾，实则是同一个变量的两段。

**★ 变量 6 上最重要的一个判断（第六类口径错误）**：
**软件栈不能当一层谈收益，要再分为「算子层」与「系统层」。**
- 算子层已基本还清：DeepGEMM-Ascend 达硬件理论上限 **99.8%**（FP8 99.5%）、FlashMLA 95%/83%
- 系统层才是主要损失来源：全链路国产训练效率仅海外 **55–65%**
- **→ 损失不在算子，在算子之外（通信/调度/内存层次/并行策略/故障恢复）。**
- **→ 这解释了 B7 的"解药是厂商驻场"：驻场调的不是算子，是系统。**

★ **第八类「自报 ≠ 可比」的性质（C4，2026-10-16）——八类中唯一"数字全真、比较全假"的一类**：前七类都伪装**状态**（未发生/未生效的说成已发生/已生效）；第八类不伪装状态，**它伪装可比性**——每个数字单独看都无衅可击（有官方出处、有规格、有测试），但分母与测试条件各不相同，跨厂商倍数比较一律不成立。五问检查：① 分母是什么（封装 TDP / all-in 设施功耗 / 相似延迟约束 / 预测租价）② 对照组命名了吗 ③ 时点是预期还是实测 ④ 绑模型/精度/batch/延迟了吗 ⑤ 软件开关对等吗（MTP/投机解码）。**这是最难防的一类，因为拆掉任何一个数字的伪装都不影响其他数字成立。**

**附加检查**：数字落在哪一栏？（模拟 / 单卡微基准 / 厂商自报 / 真实生产流量）。**跨栏换算一律不做，只并列。**

### A-2 线（`A2`，2026-09-16 新增，且修订了 A 线结论）
- **旧引擎失速**：有效公开人类文本 ~300 万亿 token，Epoch AI 估 2026–2032 耗尽，**5× 过度训练提前到 2027**；数据 2.5×/年 vs 算力 4×/年，算力正在跑赢自己的燃料。
- **新引擎点火**：ByteDance Seed / EdgeBench（2026-07-03，134 任务 / 38,000 小时）证明**环境学习曲线与预训练 scaling 同为 log-sigmoid，R²≥0.993** —— scaling law 没死，**换了输入变量**。参数分解：**S_max（天花板，由基座决定）× t_mid（到达速度，由环境学习效率决定）× β（陡峭度，由任务设计决定）**。
- **闭环已闭合**：OpenAI 官方 2026-09-06 内部报告——**3.1 agent 工作日 / 1 人类工作日**，中位研究员 >$600/天、P90 >$7,000/天；已于 2026-09 达成"自动化研究实习生"，目标 2028-03 达成"自动化 AI 研究员"。
- **真正的瓶颈是长时程自主性**：METR 50% 时间视野每 **128.7 天**翻倍（CI 104–158），但 **80% 视野远落后**；OpenAI 自述 16–32 小时任务零干预成功率仅 **23%**。→ **新曲线的斜率由"零干预成功率"决定，不由榜单分数决定。**
- **RSI 的第一个显著代价是治理不是技术**：8/7 Astra 疑似 Critical 级网络能力后，**Astra 类 GPU 配额一周内降 59.2%**。
- **对 B 线的接口**：进步函数从"训练算力"转向"交互吞吐"，因此**芯片管制从"卡训练"变形为"卡推理"**，而推理侧国产替代补位难度显著更低。

### B3 已确立的结论（供后续子课题引用）

### B6 已确立的结论（2026-09-18，供后续子课题引用）
- **★ 本层主命题不是"谁能替代 GPU"，而是：推理专用硅永远当不了主机，只能当协处理器——这不是商业失败，是物理决定的。** 它的正确位置是 **decode 池**，而 **prefill 池永远需要 GPU 的 FLOPS**。
- **★ 「25% LPU 容量」得到了物理答案**（`B1` 遗留悬案）：它是 prefill/decode 解聚的**最优资源配比**，不是商业妥协。依据——① Prefill 算力受限 → 配给 argmax(FLOP/s per \$)；Decode 带宽受限 → 配给 argmax(bytes/s per \$) ② 实测 **Prefill 成本 H100 \$0.026 < A100 \$0.042（新卡便宜 1/3），但 Decode 成本 H100 \$0.49 > A100 \$0.40（老卡便宜 1/5）——两条曲线反向** ③ **每百万 decode token 成本约为 prefill 的 10 倍**（decode 每 token 要读一遍全模型，prefill 把权重加载分摊到整个 prompt）。行业参考配比：chat 负载 1 prefill pod : 4 decode pod。
- **推论（残酷且重要）：推理专用硅的真正竞争对手不是最新 GPU，是上一代退役 GPU。** 因为 decode 的价格竞争力看"每美元带宽"，而带宽代际提升（1.64×）远慢于算力（3.2×），覆盖不了 2× 价差。**每一代 NVIDIA 退役 GPU 都会涌入推理市场，构成推理专用硅的价格天花板。**
- **适用边界一句话**：**有人在场等待 → 延迟优先；没人在等 → 吞吐优先。** 这条比任何 benchmark 都好用。依据：Nuance Labs（实时对话 Avatar，NVIDIA 参投 A 轮 \$5000 万）的行业逻辑。
- **三条固化路线 = 递增的风险阶梯**：Groq（不固化，但**每颗 LPU 仅 500MB，比 Rubin 288GB 少 576 倍**；DeepSeek V3 需 1,342 颗 / 5+ 机架）→ Etched（**固化 Transformer 架构**，宣称跑不了 diffusion/CNN/SSM/**带动态路由的 MoE**）→ Taalas（**固化单个模型权重**，只能跑那一个模型）。
- **★ 我发现的一个矛盾（Q2，最高优先级）**：Etched 一方面被报道"跑不了带动态路由的 MoE"，公司 2026 年官方口径却说"可运行任意前沿模型"。**若前者为真，则 Sohu 对 2026 全部旗舰（Kimi K3 896 专家 / DeepSeek V4 / Qwen3.5 稀疏 MoE）几乎全部失效，\$210 亿估值的前提就要重算。**
- **★ 与 A-2 线的正面冲突（本层最锋利的一条）**：A-2 判进步函数已转向"环境交互吞吐"、模型能力**每 3 个月翻倍**；而 **Taalas 的商业模式要求模型冻结**（硅片不可更改，且定制周期约 2 个月）。**若模型迭代周期 < 硅片制造周期 + 摊销周期，把权重烧进硅在经济上不成立。** Etched 的缓冲更大——固化的只是架构，而 Transformer 已稳定八年。
- **为什么服务不了闭源前沿模型（四层，缺一不可）**：① **物理**——内存装不下（Groq 500MB/颗）② **架构**——跑不了稀疏 MoE / SSM 等现代算子 ③ **商业**——WSJ 查阅投资者材料显示 **OpenAI 与 Anthropic 的推理成本均已超过收入的一半**，故必自研硅（Jalapeño / 三星 2nm），不会把命脉外包 ④ **软件**——vLLM/SGLang 默认 NVIDIA，无 day-zero 支持。**Groq 的公开定位自证："Limited to open-source models without proprietary frontier models（GPT-4, Claude）"。**
- **★ 被严重忽视的一条：绕开供应链本身就是护城河。** Cerebras 管理层明确说 wafer-scale 架构**避免了 HBM、先进封装、最先进制程节点**这些全行业短缺项；Taalas 用 TSMC **N6**、无 HBM、无先进封装、无 3D 堆叠、无液冷。**在一个人人抢 N2/CoWoS/HBM4 的年份，"不玩这个游戏"是可得性优势。** → 这构成对 `B3`「三重瓶颈」结论的**例外条款**，B3 需补注。
- **财务兑现：合同 ≠ 收入，是系统性问题。** Etched \$210 亿估值**零营收披露**（仅 >\$10 亿已签合同）；SambaNova \$110 亿、目标 2027 盈利；Cerebras 是唯一有 SEC 财报的：Q2 FY2026 GAAP 营收 \$180.1M(+74%)、core \$209.9M(+103%)、云收入 **+287%**，但 **GAAP 毛利率 10.92% vs Core 41%（差 30 ppt，因 IPO 相关 SBC 计入 COGS）**、**资本支出/销售收入 231.47%**、core 净亏仅 \$6.9M 而 GAAP 净亏 \$450.5M。**RPO \$254 亿**。股价 IPO \$185 → 首日 \$311 → 最高 \$386 → 最低 \$160.8。
- **客户集中度（Cerebras 最大风险）**：OpenAI **\$200 亿 / 750MW** 多年协议是支撑股价的单一最大信号，同时是单一对手方风险；另有相当比例收入来自 **UAE 关联客户（G42）**。新增客户：Cognition、Lovable。
- **一个被低估的金融信号**：2026 年 **General Compute 以 SambaNova SN50 ASIC（而非 NVIDIA GPU）作抵押，从 Upper90 获最高 \$4 亿信贷**。自 2021 年以来 \$200 亿+ 芯片抵押贷款几乎全以 NVIDIA GPU 为抵押品——**债务市场首次大规模接受非 NVIDIA 硅**。但要记住它只有一笔（占 2%），单笔不成趋势。
- **解聚的实测收益（供 B8 引用）**：SIVARO 实测 prefill/decode 分池 → **GPU 总成本 −38%**（真实发票）；LMSYS DeepSeek-V3 96×H100 → \$0.20/百万输出 token（约官方 API 的 **1/5**）；Inworld 自有栈 vs 通用托管 TTFT **241ms@113tok/s vs 445ms@17tok/s**；SambaNova/Intel 在 Computex 演示 Xeon6(编排)+Blackwell(prefill)+SN40(decode) → 每芯片 **2–3 倍**且复用 GPU 板载 HBM。门槛：约 16–32 张 GPU 以上才划算。
- **另有一条"最大成本杠杆"的发现（供 B8）**：**路由**。某客户把简单查询从 70B 改路由到 7B → **\$0.70 → \$0.12/千补全（−83%）**；路由开销 5ms，却省下 40ms 生成延迟。

### B8 已确立的结论（2026-10-12，供后续子课题引用）
- **★ 本层主命题不是"软件能提速多少"，是：软件栈把"买什么芯片"的决策权从芯片厂商手里拿回来。** ① 合池部署 = 只能买 GPU（因为 prefill/decode 最优硬件不同，合池只能买"两件事都还行"的，那就是 GPU 的定义）→ **CUDA 护城河的真正来源不是算子生态，是"合池部署"这个默认形态** ② 解耦后出现 **decode 池插槽**，NVIDIA 之外的硅不需要十年生态积累就能进场 ③ **插槽控制权在传输层（NIXL）**。
- **★ NVIDIA 护城河三个落点的时间序列**：CUDA 算子生态 → **每 GW 打包值**（Hopper $18B → Blackwell $25B → Rubin $40B/GW）→ **KV 传输层的默认实现（NIXL，2026 新增，当下最活跃）**。vLLM / SGLang / TensorRT-LLM / LMDeploy **四家默认集成的都是 NIXL**。
- **★ 命题纠正（本层最重要的一条）：vLLM 官方文档明说解耦不提升吞吐，只做延迟控制。** 生产里的 +75% / +525% 来自"**整套解耦栈**"（解耦 + 专家并行重配 + 大批次 + prefix 缓存 + 缓存感知路由），不是来自开关。DeepSeek 是最干净样本：解耦后 prefill 可用 EP32/DP32、decode 可用 **EP144/DP144** 把 GroupGEMM 拉满——**这是"解耦解锁的并行度重配"，不是解耦本身。** → **「开关 ≠ 栈」是本课题第 3 类口径错误。**
- **★ 解耦有四个阈值，缺一即亏**：① **模型够大**——Massed Compute 2026-08-31 自测 Qwen3-0.6B 解耦反而更慢（TTFT 18.7ms vs 聚合 12.3ms；8 路 92 vs 145 tok/s），NIXL 传输开销相对计算量占比过大 ② **prompt 8,000+ token**（经验值）③ **并发高且持续、规模 ~16–32 卡** ④ **必须 RDMA——TCP 不是降级方案，是不成立**。物理边界：传输优于重算的条件**与 prompt 长度无关**，只取决于互连带宽是否超过固定阈值（参考模型 A100 decode 池约 **10 GB/s**），现代背板全部远超。Splitwise 按层流水实测传输开销 **<7%**（不可重叠常数 A100 8ms / H100 5ms）。
- **★ 软件收益是并发的函数，不是常数**：连续批处理并发 1 只有 **1.2×**、并发 128 达 **19×**；而投机解码**相反**（batch 4 → 2.3×，batch 32 → 约归零）。**两者对并发响应相反，同一集群必须分流。** → 这解释了为什么 B1/B2/B6/B8 四条线**都在说"规模是入场券"——不是巧合，是同一个物理事实的四个投影。**
- **★ 厂商/论文/模拟 vs 生产/真实负载，普遍差 2–8 倍**：投机解码 3.0–6.5×（论文）vs 22–49%（PayPal 生产，接受率仅 35.5%）＝ 2–4 倍；Mooncake +525%（模拟）vs +75%（23,000 条真实请求重放）＝ 7 倍；TurboQuant ≥6×（论文）vs 30–40%（独立复核）＝ 3 倍；LMCache 15×（论文）vs 1.86×（真实 agentic 负载）＝ 8 倍。**这条换算规律比任何单个数字都值钱。**
- **★ PayPal 那条不是速度数字，是资本开支数字**：**单张 H100 + 投机解码 ≥ 两张 H100 + NIM → GPU 成本降 50%。**
- **★ 与 B3 的新冲突（需求侧出口）**：KV 外移（DRAM/NVMe/CXL）+ 压缩（TurboQuant 3.5 bit ≈ 1/6）从**需求侧**削减 HBM。DeepSeek 生产实测 **56.3% 的输入 token 命中盘上 KV 缓存**。Xinnor 真实 agentic 负载归一化：本地前缀缓存 1.04×／RAM 1.10×／RAM+NVMe 1.52×／**远端 NVMe-oF 也是 1.52×（共享不花代价）**／xiRAID+GDS 无 RAM 层 **1.86×**。→ **B3 的"2027 卡 HBM"需补一个需求侧缓冲项。**
- **★ 与 B6 的双向耦合（此前未指出）**：B6 把"不用 HBM = 可得性优势"列为护城河；**但若软件把 HBM 需求普遍削减数倍，这条优势会被稀释** → **B6 那条护城河的有效期取决于 B8 的进展速度。**
- **传输层是咽喉，且 AWS 已默认接受**：AWS 在 llm-d 里塞 **EFA + libfabric + NIXL**，**而不是自建传输层**（+70% tok/s，1024/1024，128 并发）。Google 开源 **TPU Raiden**（Apache-2.0，SemiAnalysis 判定与 NIXL 同层）是对这一点的确认——且 Google 文档自述"**仍在积极开发，尚未面向通用生产用途**"。NVIDIA 另一手：2026-08-04 开放 cuFile API + 存储栈给跨厂商 GitHub 组织，初始维护者含 Google/Intel/Meta——**开放邻接层以巩固核心**。

### B7 已确立的结论（2026-10-12，B 线收官，供 A×B 汇合使用）

- **★ 华为路线 = "用超节点系统级方案对冲单卡代差"，SemiAnalysis 明确背书**："芯片上落后一代，但 scale-up 方案可能领先一代"。CloudMatrix 384 = 384 颗 910C + 192 颗鲲鹏、约 300 PFLOPS、**6,912 只 400G OSFP 硅光模块**、3,168 根光纤、16 柜。**代价：功耗约为 GB200 NVL72 的 4 倍 → 这条对冲路径的天花板由 B4 的电力约束决定。** 昇腾超节点已部署 **>1,000 套、客户 >370 家**（汪涛 2026-09）。

- **★ 内存与封装是真正的咽喉**：分析师估算**中国 2026 年 HBM 产能只够支撑约 27.5 万颗 AI 芯片**；国产 CoWoS 型产能 **1.5–2.6 万片/月（<11% 全球）**，良率 **75–85% vs 台积电 98–99%**，多为 CoWoS-S（CoWoS-L 仍早期）；长电 XDFOI 0.5–0.8 万片/月（良率 75–80%）、通富 0.8–1.0 万片/月（良率 80–85%，**已通过昇腾 910B 验证**）、盛合晶微国产 2.5D 份额约 85%。**中信建投：CoWoS 型产能可得性比良率更早成为瓶颈，是 2026–2027 出货指引能否兑现的前置变量。** 2026 全链条缺口约 **200 万颗**（供给 270–280 万 vs 需求 450 万）。

### AB 已确立的结论（2026-10-12，A×B 交汇收口，供全课题引用）
1. **★ 交汇点确认为"双向锁定"，不是单向的"模型公司做芯片"。** 五个接缝：① 模型公司自研硅与编译器（A→B）② 芯片反向塑造模型架构（B→A）③ 编译器/DSL 层成为控制权落点（争夺）④ 芯片方反向进入模型层（B→A）⑤ 单位经济闭环（收敛）。题眼（Dealroom 评 Google）：**"models shaped by the silicon beneath them, silicon shaped by the models above them"**。
2. **★ OpenAI Jalapeño**（2026-06-24 发布，Hot Chips 2026 详述）：Broadcom 共同设计、TSMC 制造（**3nm-class vs 2nm-class 两口径并列**）、**从设计到流片 9 个月**（史上最快 ASIC 周期）；**13.4 PFLOPS MXFP4 / 6×HBM4 216 GiB / 15.4 TB/s / 700W**；**局部域 128 XPU = 1.7 EFLOPS + 27.5 TB HBM4（KV 常驻域内）**、6,144 对差分**无源铜背板**；全局域 **2,048 芯片/16 机架/27 EFLOPS**、**Tomahawk 6 + 混合铜光 + OCS**；**每千瓦吞吐比 GB200/GB300 高 1.5–1.9×**；全系统 **1.18 kW vs GB300 2.55 kW**。⚠ caveat：基准单轮 8k/1k、**未启用 MTP**，2027 量产时真正基线是 Vera Rubin；8.6–104.3× 那个峰值口径条件不明（待验证最高优先级）。

### C1 已确立的结论（2026-10-12，C 线第一条，供全课题引用）

1. **★ CXL 唯一的生产级大规模落地是资本套利，不是性能故事。** Meta Vistara（ISCA 2026）已**在数百万台服务器生产部署**：解耦式 ML 推理服务器数量 **−25%**、分布式缓存平均延迟 **−29%**、OOM 作业失败 **−33%**；Meta 约 **40%** 的服务器集群存在它要解决的容量限制。
2. **★ 代价必须与收益并列**：**CXL 挂的 DDR4 带宽约为本地 DDR5 的 1/10、延迟 +60%。** 看到任何 CXL 收益数字，先放这句话在旁边。
3. **Meta 之所以自研而不买现成的**（Meta 论文原话）：「Most CXL solutions bundle DRAM with the controller, **preventing the reuse of DIMM memory**, and often **do not support DDR4**… their **high power consumption and cost** further limit their appeal.」→ **这是 `B2` 云厂自研 ASIC 机制在内存侧的复现。**
4. **经济引擎是寿命错配**（Marvell 的 Khurram Malik）：**服务器刷新 4–5 年 vs DDR 寿命 10–12 年，DDR4 换代时还剩约一半寿命**；且「**直到去年为止直接加 DDR5 更便宜，这个算式随着 DDR5 涨价改变了**」。
5. **★ 5.5× 的机制不是"CXL 更快"，是"长上下文请求挪走后 GPU 批大小恢复"**（NELSSA，SK hynix × KAIST，MICRO 2026，真实硬件端到端 + Mooncake 真实 trace）。长上下文请求占满 HBM → 批大小塌到 1 → 队头阻塞。**→ 换算到结算框架是变量②（利用率）的收益，与 `AB` 的 MTP 21× 同类。**
6. **★ 同一函数的两段**：最轻的一栏（8B + 4K + 单轮 decode，真实 CXL 测试台）测得 **KV 全放 CXL 与放 DDR5 吞吐完全一致（Δ≤0.5%）**；最重的一栏（128K+ 混合长度）测得 **5.5×**。**自变量是上下文长度与批大小，不是"CXL 行不行"。**
7. **CXL 的带宽（512 GB/s）与 UALink（800 GB/s）、NVLink 5（1,800 GB/s）不是一个量级**；CXL 的优势是**延迟低（200–500 ns）、一致性、可池化**。**"CXL 替代 HBM" 从来不成立**；行业共识分层是 **HBM（热）+ 本地 DDR5（温）+ CXL 池（大容量）**，协同而非替代。
8. **★ NVIDIA 同时站在 CXL 的两侧**：① **CXL 联盟主席兼财务主管 Derek Rohde 是 NVIDIA 首席工程师**（【官方】2025-11-18）② **NVLink-C2C 官方页面写明支持 AMBA CHI 或 CXL 协议** ③ **Vera CPU 支持 CXL、Vera Rubin 平台支持 PCIe 6.4 与 CXL 3.1** ④ **2025-09 收购 Enfabrica 核心团队与技术授权** ⑤ **但域内用 NVLink 6（3.6 TB/s/GPU）+ CMX（以太网 + NVMe + DPU），不用 CXL**，且 NVLink Fusion 有"每部署至少含一件 NVIDIA 产品"的合同限制。
9. **★ 判读：NVIDIA 不反对 CXL 作为域外/CPU 侧的内存扩展标准（那不动护城河，还帮它把 Vera 卖进 x86 的地盘），但拒绝它成为 scale-up 域内的内存层（那正是护城河）。** → **不是矛盾，是变量⑤（域大小）的又一次裁决。**
10. **NVIDIA 的 CMX**（GTC 2026）：BlueField-4 + Spectrum-X + **DOCA Memos**（KV API，把以太网 flash 变成 pod 级缓存层）+ Dynamo/NIXL/Grove；**自报最高 5× TPS、5× 能效**，CMX 最高 **200 GB/s** 存储带宽；**KV 分层跨 HBM → 主机内存 → 本地 SSD → CMX → 网络存储**；NVIDIA 称之为 **"G3.5" 层**。
11. **★ G3.5 = L3.5**：华为把 OceanStor M900 定义为**基于灵衢 UnifiedBus、"一跳直连"的 L3.5 层 PB 级 KV 缓存集群**。**两个互不通气的团队把同一个中间层命名为 "3.5"，且都强调"复用而不重算"**——这是"该 tier 客观存在"的最硬证据。

20. **三条独立路径都落在变量②上，且都承认是"容量换产出"而非"带宽换产出"**：Meta 的资本套利（−25% 服务器）、NELSSA 的批大小恢复（5.5×）、Astera 的利用率提升（+75%）。**→ 与 `AB` 的 MTP 21× 是同一类结论：让已有的硅跑满，不是换更快的硅。**

### C3 已确立的结论（2026-10-12，变量 4，供全课题引用；完整版见 `C3` §9）

1. **★ 变量 4 的第一个量化基准：MXFP4 元数据占总字节约 5.9%**（32 值块 = 16 B FP4 payload + 1 B E8M0 scale = **0.53125 B/value**；相对 payload **+6.25%**）。**实际压缩率约 3.0× 而非干净的 4×。**
2. **这是可算出的确定数，不是"几个百分点"的模糊说法**；第三条独立来源（"a few percent"）与之一致。
3. **★ 一条可量化兑换的曲线：精度 ↔ 元数据字节 ↔ GEMM 开销 ↔ 硬件面积。** NVFP4（更小块 + FP8 式 scale）精度好、元数据多；MXFP4 元数据少且 **tensor core 面积省 12%**（Meta 论文，arXiv:2603.08713）。
4. **★ 元数据的代价取决于硬件设计**：gfx950 上 block scale 是 **scaled MFMA（V_MFMA_SCALE_F32_*）指令操作数流的一部分**（顺路带上）；W4A8 的 per-group scale 装不进 INT8 内层循环（额外一趟）。**→ 国产卡要跑 MXFP4 必须支持 scaled MFMA 类指令。**
5. **★★ 元数据是控制信息，不是数据。** MoE 路由索引 + 权重只有**约 2 MB**（batch 32 × seq 2048），却**决定 All-to-All 通信模式，而 All-to-All 消耗总运行时间的 40–50%**；通信缓冲区峰值 **1.2 GB**；8×H100 实测稠密 120 ms vs MoE P95 185 ms，**多出的 65 ms 中 22 ms 在 PCIe 搬运**。
6. **★ 变量 4 的定义修正：按两层衡量——L1 字节占比 + L2 撬动量。** 只测 L1 会得出"元数据不重要"的错误结论（2 MB 撬动 40–50% 运行时间）。
7. **压缩注意力索引同理**：Lightning Indexer 用 **FP4** 打分只为选出 **Top-512/1024**，但它决定后面哪些块要被读。实测加 HCA 后 KV 从 38% → **9.7%**、TTFT 从 1.2 s → **0.38 s**。
8. **★ 上升机制五环**（中兴论文只给了定性判断）：注意力压缩 **m=4 → m'=128** ／ Lightning Indexer FP4 化 ／ **HCA token 强制 4 bit（已退化为纯存在性标记）** ／ KV 混合存储格式（RoPE 保持 BF16、其余 FP8）／ 权重 FP4 化。**数据在被压缩，元数据在被保留甚至强化。**
9. **★★ HBM 正在从"数据层"变成"索引层"**：DeepSeek V4-Pro（1.6T MoE）1M 上下文仅需 **5.48 GB HBM**（GLM5 60 GB / Qwen3-235B-A22B 89 GB / GPT-5.5 级 **180+ GB**）；机制是 **Keys（压缩索引）留 HBM、Values 整个卸载到系统内存/本地存储/国产 NAND·LPDDR**。
10. **与 `C1` 完美衔接**：C1 把 KV 搬到 G3.5/L3.5 中间层，C3 说明 HBM 里留下的是索引。**两条独立路径指向同一结构。** → **`B3` 的 HBM 需求模型要加"单位 HBM 承载的 token 数"。**
11. **硬件侧的响应与缺口不在同一层**：昇腾 950PR 做的是**数值格式**硬件加速（MXFP8/MXFP4 原生支持 + 融合 kernel + 多流并行降低混合注意力访存）；中兴论文指的是**压缩注意力索引检索**的硬件加速缺失——**后者目前无人做，是 `B6`/`B7` 的空白机会点。**
12. **成本兑现是真的**：1M 上下文推理成本降至 **GPT-5.5 的 1/70**；V4-Pro 输入 0.025 元/百万 token；DeepSeek **首次把昇腾与 NVIDIA 并列写入硬件验证清单**（通用推理 1.50–1.73×、延迟敏感最高 1.96×），**8 家国产芯片实现 Day-0 全栈适配**。
