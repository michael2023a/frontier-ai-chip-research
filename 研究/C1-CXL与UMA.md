## 〇、为什么要单开这条线

CXL 在 B 线里被指向了三次，每次都是**从别的层绕回来的**：

| 指向它的地方 | 当时的话 |
|---|---|
| `B3` §5.1.2 | Samsung 实测 CXL 承载 KV，跨 8 张 Blackwell 达 DRAM 性能约 92% |
| `B5` | Marvell 的 XConn 资产同时供应 UALink 交换机与 CXL 交换机——两条"绕开 NVIDIA"的路在同一条供应链上交汇 |
| `B7` | **未发现中国侧 CXL 进展，这是明显缺口** |

`B8` 收口时又补了一刀：解耦推理的价值取决于 **KV 能不能搬得动**。而搬 KV 这件事，在 2026 年已经分化成三条互不相通的技术路线。

**所以这条线不是"CXL 行业调研"，是回答一个更具体的问题：**

> **把内存搬到算力之外，到底有几种搬法？各自的代价是什么？中国在哪条路上？**

## 一、分析单位（★ 先钉死，再动手）

**这条线不能按公司拆**（同一家 Marvell 同时做内存扩展、近内存计算、CXL 交换三件事），**也不能按产业层拆**（CXL 同时是互连、是内存、是存储）。

**本线的分析单位 = 内存解耦的三条路线**，每条再按两个维度交叉：

| 维度 | 取值 |
|---|---|
| **维度 1 · 语义** | 一致性内存语义（load/store）／网络存储语义（RDMA + KV API）／私有总线语义 |
| **维度 2 · 落点** | 本机扩展 → 柜级池化 → 跨机架 → 集群级 KV 层 |
| **维度 3 · 有无生产流量** ★ | 规范 / 样品 / 试点 / **百万台级生产** |

**★ 维度 3 是本线的主轴。** 前两个维度很容易被厂商叙事填满，**只有第三个维度能区分"存在"和"生效"**。

### 1.1 三条路线一览

| 路线 | 语义 | 代表产物 | 谁在推 |
|---|---|---|---|
| **A · 一致性内存**（CXL 系） | load/store，OS 看见一个无 CPU 的 NUMA 节点 | Astera Leo、Marvell Structera X/A/S、SK hynix CMM-Ax / CMM-DDR5、Samsung CMM-D / CMM-B、Micron CZ122、**澜起 MXC**、Panmnesia PANSWITCH | Intel / AMD / 三星 / SK 海力士 / Marvell / Astera / 澜起 |
| **B · 网络 + 存储语义**（不走 CXL） | RDMA + key-value API，应用显式调用 | **NVIDIA CMX**、DOCA Memos、BlueField-4、Spectrum-X、Dynamo + NIXL | NVIDIA |
| **C · 私有统一总线 + 全光** | 协议归一、全局统一编址，一跳直连 | **华为灵衢 UnifiedBus**、鲲鹏超节点 256TB 统一内存池、OceanStor M900 | 华为 |

**★ 三条路线的终点是同一个东西**：一个位于 HBM 与网络存储之间、专门放 KV 的**中间层**。
而且这个层已经被两条完全独立的栈**各自命名为 "3.5 层"**——NVIDIA 叫 **G3.5 context tier**，华为叫 **L3.5 层 PB 级 KV 缓存**。两个互不通气的团队用了同一个层号，说明这个 tier 是客观存在的结构，不是营销话术。

## 三、★ 唯一的生产级大规模落地：Meta Vistara

**这是整条线最重要的一节。** 前面所有产品都是"存在"，这一节是"生效"。

### 3.1 它是什么

【一手三方】Meta 在 **ISCA 2026（2026-06-27~29，Raleigh）** 发表 Vistara 论文，并已**在数百万台服务器上生产部署**。

| 项 | 内容 |
|---|---|
| 芯片 | Meta **自研** ASIC，CXL 2.0 / 1.1 兼容 **Type-3 内存扩展器**，PCIe Gen5 x16 |
| 内存侧 | 2 条独立 72-bit DDR4 通道，最高 3200 MT/s；每 ASIC 最高 **256 GB**（用 64 GB DIMM）；**生产部署实际用 32 GB DIMM**（受退役库存限制） |
| 控制 | **双自研 RISC-V 核**（不授权外部 MCU IP），自写固件 |
| 平台 | MemServer：AMD EPYC Turin（158 核 / 316 线程）+ 768 GB DDR5-6400 + 2× Vistara（PCIe 5.0 x8）提供 256 GB DDR4-2400 → **单机约 1 TB** |
| 软件 | 自研 Linux 内核；CXL 驱动把 DDR4 池呈现为**一个无 CPU 的 NUMA 节点**；**Transparent Page Placement（TPP）** 按负载决定本地/扩展内存比例，**对延迟敏感应用自动关闭 CXL 池** |

### 3.2 它拿到什么

| 结果 | 数值 |
|---|---|
| 解耦式 ML 推理**服务器数量** | **−25%**（上限） |
| 分布式缓存**平均延迟** | **−29%** |
| **OOM 作业失败** | **−33%** |
| 适用面 | Meta 约 **40%** 的服务器集群存在 Vistara 要解决的容量限制 |

**延迟 −29% 是反直觉的**：容量变大 → cache miss 变少 → 网络取数变少，抵消了 CXL 的访存代价还有余。这一条值得单独记住——**它是"容量换延迟"而不是"带宽换延迟"**。

### 3.3 ★ 它付出什么（这一栏必须和上面并列）

> **CXL 挂的 DDR4，带宽约为本地 DDR5 的 1/10（10× lower bandwidth），延迟高约 60%。**

**→ 看到任何 CXL 收益数字，先把这句话放在旁边。**

### 3.4 两个产业侧的关键判断

**① Meta 为什么不买现成的？**（Meta 论文原话）
> 「Most CXL solutions bundle DRAM with the controller, **preventing the reuse of DIMM memory**, and often **do not support DDR4**, which is necessary for repurposing old memory. Additionally, their **high power consumption and cost** further limit their appeal.」

即：**商用 CXL 模组把 DRAM 和控制器绑死、不支持 DDR4、功耗和成本都不合算。** Meta 自研不是因为想造芯片，是因为**商品硅不满足它的三个约束**（可复用 DIMM / DDR4 / 功耗）。这与 `B2` 的"云厂自研 ASIC"结论是同一个机制，只是发生在内存侧。

**② Marvell 的 Khurram Malik（存储与内存子系统产品组合副总裁）给出的经济引擎**：
> 服务器刷新周期 **4–5 年**，而 DDR 内存寿命 **10–12 年** —— **DDR4 在服务器被替换时通常还剩约一半寿命**。且「直到去年为止，成本一直是 CXL 内存扩展的主要障碍，因为直接加 DDR5 更便宜；**这个算式随着 DDR5 涨价改变了**。」

**③ Ameet Sanghavi（NVIDIA 的 PCIe/CXL 后硅验证负责人）给出的行业校准**：
> 「CXL 内存扩展在**少数重度投入的超大规模厂商**中已越过试点进入生产；**除此之外的行业基本还在试点阶段**，DDR5 涨价是推动更多企业开始评估的主因。」

他还点出普通企业的三重困难：**DIMM 类型匹配 → 板卡供应商验证 → 第三方服务器 BIOS 差异**；出故障时要同时拉进 ASIC、板卡、服务器三方。

**→ 这条引语的分量在于它是 NVIDIA 的人说的**：NVIDIA 既不否认 CXL 已进生产，也明确划了"只有少数超大规模厂商"的边界。

## 四、性能收益到底从哪来（★ 拆开 5.5×）

### 4.1 NELSSA：真实硬件端到端，但机制不是"更快"

【论文·已录 MICRO 2026，arXiv:2607.26633，2026-07-29 投稿】SK hynix × KAIST（Jongse Park 组）的 NELSSA，跑在 **CMM-Ax / Structera A 真实硬件**上，不是模拟。

| 项 | 内容 |
|---|---|
| 结果 | 混合长度负载下 **decode 吞吐 +5.5×**（tok/s）、**P99 延迟 −15×**（对比 GPU-only 基线） |
| 负载 | 真实 trace（Mooncake 会话 trace：**约 34% 请求 <4K token，同时有 >100K token 的请求在跑**） |
| 机制 | 按长度路由：短上下文 → GPU，长上下文 → PNM 层；上下文增长时**运行时迁移**，不重算、不驱逐 |
| 通信 | 控制面 gRPC/TCP，**数据面 KV 走 RDMA（RoCEv2）**；KV 按 **head-wise** 分片跨多 PNM 模块 |
| **收益来源（论文自述）** | **"restoring effective running batch size on GPUs"** —— 恢复 GPU 上有效运行批大小，**缓解长上下文请求造成的队头阻塞（HoL）** |

**★ 机制判读（这是本节的核心）**：
长上下文请求把 HBM 占满 → 调度器无法接纳新请求 → **运行批大小塌到 1** → 后续短请求全部排队等着（HoL 阻塞）。论文在单张 H100（94 GB）上展示了这个"批大小崩溃"现象。

**→ 5.5× 不是"CXL 更快"，是"把长上下文请求挪走之后，GPU 的批大小恢复了"。**
**→ 换算到结算框架：它是变量②（利用率）的收益，不是带宽的收益。** 这一点和 `AB` 的 MTP 21× 是同一类——**都是"让已有的硅跑满"，不是"换更快的硅"。**

**口径**：真实硬件端到端原型 + 真实 trace，但**不是生产流量**。按 §5.3.1 的附加检查，它落在「端到端原型」这一栏，**不与生产流量跨栏换算**。

| **R/W Cache【论文·ACM Turing China 2026】** | **KV 放 CXL 与纯 DDR5 吞吐完全一致（Δ ≤ 0.5%），省 50% DDR5** | **真实 CXL 测试台**，llama.cpp / Llama-3-8B Q4_K_M，WildChat / GovReport / PG19，**ctx=4096** | 单卡微基准（★ 见下） |

**★ R/W Cache 那条极重要**：在真实 CXL 硬件上，8B 模型、4K 上下文、decode 阶段，**把 KV 全放 CXL 与放 DDR5 吞吐一模一样**。论文的原话是「KV-on-CXL is zero-cost」。
**→ 但这恰恰说明它落在"最轻的一栏"**：8B 模型 + 4K 上下文 + 单轮 decode 是**最不容易暴露带宽差距**的配置。**NELSSA 的 5.5× 出现在 128K 以上的长尾上，R/W Cache 的 0% 出现在 4K 上——两者不矛盾，是同一个函数的两段，自变量是上下文长度与批大小。**

### 4.3 反证：CXL 的硬代价

| 代价 | 数值 | 来源 |
|---|---|---|
| CXL 内存延迟 | **200–500 ns**（对比本地 DDR 的 80–100 ns） | 【产业媒体】三织物对比表 |
| 随机访问 workload 下 CXL vs 本地 DDR | **高约 1.5–2 倍**（同一量级） | 【厂商自报】晶铁半导体 CXL 2.0 方案实测 |
| Meta 实测 CXL-DDR4 vs 本地 DDR5 | **带宽 1/10、延迟 +60%** | 【一手三方】ISCA 2026 |
| 三织物延迟档位 | CXL（200–500 ns，PCIe SerDes，低误码低延迟低带宽）vs UALink / NVLink（以太网式 SerDes，更高带宽换更高延迟与误码） | 【产业媒体】 |
| CXL 4.0 带宽 | x16 PCIe 7.0 约 **512 GB/s** 单向；bundled 示例 768 GB/s 单向 / 1.536 TB/s 双向 | 【官方】CXL 联盟白皮书 |

**★ 一张表看清 CXL 的定位**：CXL 的带宽（512 GB/s）与 UALink（800 GB/s/加速器）、NVLink 5（1,800 GB/s）**不是一个量级**；它的优势是**延迟低、一致性、可池化**。
**→ "CXL 替代 HBM" 从来不成立，行业共识的分层是 HBM（一级热存）+ 本地 DDR5（二级温存）+ CXL 池（三级大容量存），两者是协同不是替代。**

## 五、路线 B · NVIDIA 不走 CXL：CMX 上下文内存存储

### 5.1 CMX 是什么

【官方】NVIDIA CMX（Context Memory Storage）平台，GTC 2026 发布（CES 2026 先以 ICMS 名义预告）：

| 层 | 元件 |
|---|---|
| 硬件 | **BlueField-4** 存储处理器（集成多核 NVIDIA CPU + 高带宽内存），管理 NVMe SSD |
| 网络 | **Spectrum-X Ethernet**（RDMA/RoCE，拥塞控制 + 自适应路由 + 无损） |
| SDK | **DOCA Memos** —— 暴露 key-value API，把以太网挂的 flash 变成 **pod 级缓存层**；应用保持 stateless |
| 编排 | **Dynamo**（分布式推理框架，KV-aware 路由与复用）+ **NIXL** + **Grove**（拓扑感知编排，感知 KV 局部性） |
| 层级 | **KV 分层跨：GPU HBM → 主机内存 → 本地 SSD → CMX → 网络存储**；NVIDIA 称之为 **"G3.5" 层** |
| 带宽 | CMX 最高 **200 GB/s** 存储带宽；BlueField-4 在 **800 Gb/s** 下线速加密与 CRC，不消耗 Grace CPU 周期 |

### 5.2 NVIDIA 自报的收益（厂商口径）

- 相对通用存储：**最高 5× TPS**、**最高 5× 能效**、2× 更快数据摄取
- 能效论证：KV cache 是**瞬态、可重算**的数据，不需要企业级存储那套持久性/冗余/后台一致性检查 → 砍掉这些开销换来 5× 能效
- 生态：存储伙伴 Cloudian / DDN / Dell / Everpure / Hitachi Vantara / HPE / IBM / MinIO / NetApp / Nutanix / VAST Data / WEKA；
  采用方 CoreWeave / Crusoe / IREN / Lambda / Mistral AI / Nebius / OCI / Vultr；**STX 平台 2026 下半年上市**

### 5.3 ★ NVIDIA 同时站在 CXL 的两侧（本节最关键的判读）

把以下五条**并列**，不要替它取舍：

| # | 事实 | 来源 |

**判读**：
> **NVIDIA 不反对 CXL 作为 CPU 侧的内存扩展标准**（那不动它的护城河，反而能帮它把 Vera CPU 卖进 x86 的地盘），

> **→ 这不是矛盾，是变量⑤（域大小）的又一次裁决：CXL 是域外的标准，NVLink/CMX 是域内的标准。**

### 6.2 与 NVIDIA 的惊人重合

NVIDIA 把 KV 层叫 **G3.5**，华为把 KV 层叫 **L3.5**。两者：

**→ 两个互不通气的团队把同一个层命名为 "3.5"，这是本轮最硬的"结构客观存在"证据。**

## 八、与结算框架的对接

### 8.1 这条线落在七个变量里的哪几个

| 变量 | C1 的贡献 |
|---|---|
| **① 每兆瓦 token 数** | CXL/CMX/灵衢三条路都在做同一件事：**用便宜介质承接 KV，让 HBM 只留最热的**，从而抬高单位功率的 token 产出。Meta 的 −25% 服务器数量就是直接体现 |
| **② 利用率** | **本线的主战场**。NELSSA 的 5.5× 机制是"恢复批大小"；Meta 的 −29% 延迟是"容量换延迟"；Astera 的 +75% GPU 利用率是同一件事的第三个说法。**三者互相独立地指向同一个变量** |
| **③ KV / 内存需求** | CXL 提供的是**容量**不是带宽，因此它缓解的是 KV 的容量压力；`B3` 的 HBM 硬约束因此有了第二条出路 |
| **⑤ 域大小** | **裁决变量**。CXL = 域外/柜级；NVLink 6 + CMX = 域内/pod 级；灵衢 = 超节点内统一编址。**同一个"内存池化"，域不同则结论相反** |
| **⑥ 编译器中间层** | 软件栈决定能不能吃到硬件收益：Meta 靠自研内核 + TPP；NVIDIA 靠 Dynamo + NIXL + Grove + DOCA Memos；浪潮靠 MantaKV。**硬件接了调度跟不上，等于没接**（从业者原话：「冷热数据识别、软件调度跟不上，硬件接了也用不好」） |

### 8.2 ★ 与 `B8` / `AB` 的接口：CXL 池化是"解耦之争"的第三方答案

`AB` 记录 OpenAI 在 Jalapeño 上**明确不做 PDD**，理由是「整颗芯片可能仅仅因为属于错误的池而闲置……且解耦破坏局部性」。
`B8` 记录四个阈值下解耦有 +75%/+525%。

**CXL 池化给出了第三种解法（浪潮 MantaKV）**：
> 把 P 节点产生的 KV **集中写进 CXL 池化共享内存**，D 节点直接读，**不需要"先卸载到本地 SSD 再传给 D"这两次搬运**。
> **→ 它既不是"每个节点各管各的"（解耦），也不是"全局统一池"，而是"把共享层放在两者都能一跳直达的地方"。**

**裁决仍然回到变量⑤（域大小）**：
- CXL 池化的域 = **柜级**（跨柜要走网络，届时又回到解耦的问题）
- OpenAI 的域 = **128 XPU 局部域 + 27.5 TB HBM4**，KV 留在域内更划算
- **→ 域够大且 KV 常驻 → 统一池/共享层；域小且 KV 要跨机架搬 → 解耦。CXL 把这条分界线往外推了一格，没有取消它。**

### 8.3 ★ 建议新增第七类口径错误：「规范 ≠ 启用」

前六类错误见 `00` §5.3.1。本线暴露出第七类，**性质与第五类（份额≠有效算力）同类，都是"把已存在的当成已生效"**：

| 类型 | 出处 | 实例 |
|---|---|---|
| **规范 ≠ 启用** | `C1` | CXL **4.0** 已发布（128 GT/s），但 **2026 年真实主机世代仍是 2.0**；支持 PCIe 6.x Retimer 的服务器 CPU **2027 才量产**；**2026 年真正启用 CXL 的服务器比例可能仅约 1%**；TechInsight 预测 CXL 在服务器 DRAM 份额 2024 近乎为零 → 2030 约 15% |

**与其他类型的区别**：前四类（宣布≠开工、合同≠收入、开关≠栈、模拟≠生产）说的是"**还没发生**"；第五类（份额≠有效算力）和第七类（规范≠启用）说的是"**发生了但没生效**"。
**第七类更隐蔽**：规范编号是公开的、可查的、看起来很硬的数字（4.0、128 GT/s、4,096 节点），**但它描述的是能力上界，不是部署状态。**

## 十、结论（17 条）

1. **CXL 唯一的生产级大规模落地是资本套利，不是性能故事。** Meta Vistara 已在数百万台服务器生产运行，收益是服务器数量 −25%、缓存延迟 −29%、OOM −33%，**来源是让退役 DDR4 不报废**。
2. **它的代价必须和收益并列：CXL 挂的 DDR4 带宽约为本地 DDR5 的 1/10、延迟 +60%。** 看到任何 CXL 收益数字，先放这句话在旁边。
3. **Meta 之所以自研而不是买，是因为商品 CXL 模组把 DRAM 与控制器绑死、不支持 DDR4、功耗成本不合算。** 这是 `B2` 云厂自研 ASIC 机制在内存侧的复现。
4. **经济引擎是"寿命错配"：服务器 4–5 年 vs DDR 10–12 年，DDR4 换代时还剩约一半寿命**，且 DDR5 涨价使复用从"不划算"变"划算"。
5. **5.5× 的机制不是"CXL 更快"，是"长上下文请求挪走后 GPU 批大小恢复"。** 换算到结算框架是**变量②利用率**的收益，与 `AB` 的 MTP 21× 同类。
6. **最轻的一栏（8B + 4K + 单轮 decode）测得 KV 全放 CXL 与放 DDR5 吞吐完全一致（Δ≤0.5%）；最重的一栏（128K+ 混合长度）测得 5.5×。** 两者不矛盾，是同一函数的两段，自变量是上下文长度与批大小。
7. **CXL 的带宽（512 GB/s）与 UALink（800 GB/s）、NVLink 5（1,800 GB/s）不是一个量级**；它的优势是延迟低、一致性、可池化。**"CXL 替代 HBM" 从来不成立。**
8. **行业共识分层是 HBM（热）+ 本地 DDR5（温）+ CXL 池（大容量），协同而非替代。**
9. **NVIDIA 同时站在 CXL 的两侧**：联盟主席是 NVIDIA 首席工程师、NVLink-C2C 官方支持 CXL、Vera 支持 CXL 3.1、收购 Enfabrica —— **但域内用 NVLink 6 + CMX（以太网 + flash），不用 CXL**。
10. **判读：NVIDIA 不反对 CXL 作为域外/CPU 侧的内存扩展标准，但拒绝它成为 scale-up 域内的内存层。** 这不是矛盾，是变量⑤（域大小）的裁决。
11. **NVIDIA 与华为各自独立地把 KV 层命名为 G3.5 / L3.5，且都强调"复用而不重算"。** 两个互不通气的团队用同一个层号 —— 这是"该 tier 客观存在"的最硬证据。
12. **三条路线（CXL 一致性内存 / 以太网+NVMe / 私有统一总线）在争同一个中间层，落点从单机到 pod 到超节点不等。**
13. **★ 修正 `B7`：中国侧不是空白，是「分裂」。芯片层澜起全球首个试产 CXL 3.2 MXC 且已进三星/SK 海力士供应链；系统层华为走私有灵衢（256 TB 统一内存池、RTT 2 µs），不走 CXL。**
14. **一句话：中国卖 CXL 的"心脏"给三星和 SK 海力士，但中国自己的系统不跑 CXL。芯片是生意，总线是主权。**
15. **★ 国产最薄弱环节是大通道 CXL Switch**：数渡 PCIe 6.0/CXL 仍在研发未投片、澜起 2026 才计划完成工程样片。替代顺序是 **Retimer 先行 → MXC 跟进 → Switch 最后**；境外 Switch 交期已 >50 周，替代窗口是打开的。
16. **★ 建议新增第七类口径错误「规范 ≠ 启用」**：CXL 4.0 已发布，2026 主机仍是 2.0，服务器启用率可能仅约 1%。**规范编号描述的是能力上界，不是部署状态。**
17. **CXL 池化是 `B8`/`AB` 解耦之争的第三方答案**（浪潮 MantaKV：两次搬运合并为单次写入），**但它没取消变量⑤的分界线，只是把它往外推了一格**——柜级池化成立，跨机架仍要回到解耦。
