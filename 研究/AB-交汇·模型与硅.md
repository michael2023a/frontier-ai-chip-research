## §0 命题：交汇点比"模型公司自研芯片"更深

`A1b` 与 `A2` 已经两次指出交汇点是"模型公司开始反向进入芯片与编译器层"（Kimi K3 的芯片原型与 MiniTriton）。**那个判断是对的，但浅了。**

检索下来，真正的结构是这样的：

> **这不是"模型公司开始做芯片"这一个方向的事，而是五个方向上同时发生的双向锁定。模型公司在定义硅；硅在定义模型架构；编译器层成为双方争夺的控制点；芯片方反过来承担了模型适配的工程负担；而两边的所有决策最终都收敛到同一个分母——每兆瓦产出的 token 数。**

**★ 一条最贴切的定义**（Dealroom 对 Google 的表述，可直接当作本文件的题眼）：
> **"models shaped by the silicon beneath them, silicon shaped by the models above them"**
> ——硅之下的模型塑造硅，硅之上的硅塑造模型。

**以及一句最讽刺的事实**（SemiAnalysis 评 OpenAI）：
> **"像 GPT 5.6 Sol 这样的 OpenAI 模型目前跑在 NVIDIA GPU 上，它们被用来设计一颗对 CUDA 护城河构成真实威胁的芯片——NVIDIA 自己的 GPU 正在实时助推它的潜在继任者。"**

## §1 五个接缝分解表

| # | 接缝 | 方向 | 一句话证据 |
|---|---|---|---|
| **①** | **模型公司自研硅与编译器** | A→B | OpenAI Jalapeño **9 个月流片** + 自研 Gluon DSL；Kimi K3 自研 MiniTriton + 48 小时芯片原型 |
| **②** | **芯片反向塑造模型架构** | B→A | 2026 已进入 **"Inference-Aware Architectures"** 时代：模型在预训练阶段就被设计为适配低精度硬件 |
| **③** | **编译器/DSL 层成为控制权落点** | 争夺中 | 同一层里挤进 Triton / Gluon / TileLang / Pallas / NKI / CANN / MiniTriton——**谁定义中间层，谁定义硬件可替代性** |

| **⑤** | **单位经济闭环** | 收敛 | **同一个模型、同一块硅，仅软件差异造成每百万 token 成本 20 倍价差** |

## §2 接缝①：模型公司自研硅与编译器（A→B）

### §2.1 OpenAI · Jalapeño —— 本轮信息量最大的一个案例

**发布**：2026-06-24（Infrastructure Day），Hot Chips 2026 详述。Broadcom 共同设计（物理设计/SerDes/封装），TSMC 制造（⚠ **3nm-class**（NAND Research、TechInsights）vs **2nm-class**（Exiy），两口径并列），Celestica 做板卡与机架集成。

| 维度 | 数字 |
|---|---|
| **开发周期** | **从初始设计到流片 9 个月**——OpenAI 称为史上最快 ASIC 周期 |
| 单芯片 | **13.4 PFLOPS MXFP4**；**6 组 HBM4 / 216 GiB / 15.4 TB/s**；TDP 700W（实测持续 ≤550W） |
| **局部域** | **128 加速器 = 1.7 EFLOPS（4-bit）+ 27.5 TB HBM4**，600 GB/s 本地集合网络，**KV cache 常驻此域**；6,144 对差分**无源铜背板** all-to-all，每 XPU 单向 4.8 Tb/s |
| **全局域** | **2,048 芯片 / 16 机架 = 27 EFLOPS + 432 TiB**；Broadcom **Tomahawk 6**（102.4 Tb/s）半扁平两级 Clos @200 GB/s；**混合铜-光 rail + OCS** |
| 机架构成 | Katsu Host Tray（双 AMD EPYC Turin + 1.5TB DRAM）／Vindaloo ASIC Tray（1U、8 颗、每柜 128 XPU）／Chana Switch Tray |
| 性能 | **每千瓦吞吐比 GB200/GB300 高 1.5–1.9×**（峰值效率配置下达 8.6–104.3×，⚠ 口径极端）；端到端延迟低 1.7–3.6×；**全系统级 1.18 kW vs GB300 2.55 kW** |
| 部署 | 2026 年底有限部署，2027 扩大；**二代已深度开发中、三代已启动** |

**★ 三条最值得记的：**

1. **★ AI 辅助设计（不是"AI 写芯片"，但比想象中实在）**：OpenAI 用**自己的模型**在 **XLS 硬件描述语言**上做 "continuous convergence" 工作流，**BF16 乘法相比人类工程基线提升 56%**。硬件负责人 Richard Ho 在 Synopsys Converge 的说法很关键：不是"写代码-编译-测试"的直线循环，而是派生成百上千个 agent **夜间跑验证、时序收敛、面积优化**，"sub-intelligence 读回日志、定位 debug、然后调参数和工具流"。→ **这是"并行化人类瓶颈"而不是"替代人类"。**
2. **★ 按推理阶段激活/门控硬件模块**：prefill（计算密集）/ decode（带宽密集）/ 投机解码小 batch draft model 三种形态下，Jalapeño **开关不同的计算、内存、网络块**，降低混合负载下的空转功耗。→ **一颗"均衡"芯片支持三种形态，不需要异构机队。**
3. **★ 但战略定性很清楚**：TechInsights——**"Jalapeño 是 captive silicon 且只做推理，不能视为 NVIDIA 的直接竞争对手"**。OpenAI 训练继续依赖 NVIDIA（双方战略合作到 2030 年最高 **$6,000 亿**算力）。**策略不是"替代"，而是"在经济学明显占优的新模型/高量模型上部署 Jalapeño，用多供应商机队服务不同性能档与价格档"。**

⚠ **必须标出的 caveat**（SemiAnalysis / kad8）：初始基准是**单轮 8k/1k** 负载；**未启用 MTP 或投机解码（STP）**，软件仍有余量；**2027 年量产时真正的对比基线是 Vera Rubin，不是 Blackwell**。

### §2.2 ★ Gluon：模型公司在定义"布局"这门数学

**Gluon = 建在 OpenAI 自己的 Triton 之上的 DSL。**

| 特性 | 内容 |
|---|---|
| 保留 | Triton 的 **SPMD** 编程模型 |
| 暴露 | **底层抽象**——在 NVIDIA 上直接映射到 PTX 的 MMA / TMA / mbarrier 指令 |
| **★ 最独特的抽象** | **Layout（布局）**：定义硬件资源（如 warp 9 的第 5 个寄存器）↔ 张量元素（如第 6 行第 7 列）的映射 |
| **★ 数学基础** | **Linear Layouts**——OpenAI 发明并发表的**布局代数**，用 **𝔽₂ 上的二元矩阵代数**形式化表示张量/寄存器/内存之间的映射 |
| 带来的能力 | **可证明正确的布局转换**、**最优内存 swizzling**；把组合复杂度从"手工枚举布局"降为"代数推导" |
| 编程模型 | **每个 Gluon 程序映射到一个持久线程**；**由程序员而非硬件调度器分配工作到 tile**；kernel 包含整个推理循环，最小化 CPU 参与 |
| 其他 | TensorInfo（显式编码布局的抽象）；每核提供数据预取与**解耦乱序单元**（可编程等待预取数据、信号量锁定） |

**★ 为什么这条重要**：**Gluon 是"模型公司定义硬件抽象层"的第一手物证。** OpenAI 不是在适配某颗芯片的既有栈，而是在**发明一套代数**来描述"张量怎么落到硅上"。→ **这是 A→B 最深处的一次进入。**

**配套**：OpenAI 用 **Codex 生成 kernel 与预取策略**（针对实测 trace harness 评估，而非静态编译启发式）；有 **chilisim 模拟器，精度在实测硬件 5% 以内**。
**迭代速度**：不到两周某些交互场景吞吐提升 **>2×**；**8 天内从 TP8 扩展到机架级 TP32**。

### §2.3 Kimi K3 · MiniTriton 与芯片原型（A 线原有线索的一手补强）

【官方·Moonshot，kimi.com/blog/kimi-k3】：
- **MiniTriton**：基于 **MLIR** 自建 **tile 级 IR 层** + 完整优化 Pass + **PTX 代码生成流水线**；在 Roofline 基准上**达到或超过 Triton 与 torch.compile**，部分负载优于 Triton；**能稳定支撑端到端 nanoGPT 训练**（损失曲线与参考基本一致）。
- 官方定性：**"K3 能构建一套完整且自洽的端到端编译器系统——覆盖 DSL 前端、IR 优化、PTX 代码生成与运行时，而不仅仅是编写孤立的算子内核。其从零实现的 Tensor Core 路径，已能与经过长期深度优化的 Triton 技术栈相媲美。"**
- **芯片原型**：48 小时自主 Agent 运行，基于**开源 EDA 工具 + Nangate 45nm 工艺库**，完成构建/优化/验证。**4 mm²**（3.981 mm²）、**146 万标准单元**、0.277 MB SRAM、**带融合反量化的 INT4 MAC 阵列**、100 MHz 时序收敛、**仿真解码吞吐 >8,700 token/s**。官方原话：**"一颗由模型设计、为模型服务的芯片。"**
- **GPU kernel 优化**：24 小时沙箱内 profile/重写/benchmark 四个任务（AttnRes、KDA、**512 head-dim MLA kernel**），跨 NVIDIA Hopper 与另一家 GPGPU，**与 Fable 5（带 fallback）竞争力相当**，大幅超过 Opus 4.8 / GPT 5.6 Sol / GPT 5.5。

⚠ **口径**：45nm、100MHz、仿真、nano 模型——**这是能力证明，不是产品**。与 Jalapeño（3nm、真实流片、13.4 PFLOPS）相差约 6 个数量级的应用层级，**不可比，只并列。**

### §2.4 Google · TPU：唯一把这条接缝跑了十年的

【官方·Google Cloud Blog，Ironwood】+ 第三方：
- **Ironwood（TPU v7）**：单芯片 **192 GiB / 7.4 TB/s**（8 组 HBM3E）；**42.5 EFLOPS FP8**/superpod；**9,216 芯片 / 144 cubes**；cube = 64 芯片 3D Torus（ICI）；**ICI 总带宽 88,473.6 Tbps（11,059.2 TB/s）**；**1.77 PB 全局直接可寻址 HBM**（共享内存多处理器世界纪录）。
- **★ 双管编译器策略**（Google 官方原话）：**"XLA 的编译器中心方法提供强大的性能基线（把算子融合成能喂饱 MXU 与 VPU 的优化 kernel），然后由自定义 kernel（Pallas）在特定模型-硬件组合上达到峰值——这个双管策略是 co-design 的基本原则。"**
- **SparseCores 第四代**：较上代 **2.4× FLOPS**，专门承担 **embedding 稀疏计算**与**卸载集合通信**——**与主 TensorCore 完全并行执行，消除通信等待**。→ **这是"模型公司的痛点（通信等待）被直接烧进硅"的典型案例。**
- **perf/watt**：**2× vs Trillium**；约 **29.3 TFLOPS/W**（另一源）；比 2018 年第一代 Cloud TPU 高近 **30×**。
- **★ TPU 8t / 8i（2026-04-22 Cloud Next）**：
  - **8t（训练）**：**9,600 TPU/pod**、**2 PB 共享内存**、约 **3× Ironwood** 算力、**2× perf/watt**（另源：121 EFLOPS FP4；CNBC：同价格下 2.8× Ironwood 性能）
  - **8i（推理）**：**1,152 TPU/pod**、**3× 片上 SRAM（384 MB）**、HBM **288 GB**，定位"**成本高效地运行数百万 agent**"；CNBC：推理好 80%
- 路线图：**5 年 1,000× 算力**。

**★ 两条结构性判读：**
1. **★ 训练/推理拆成两颗芯片，中美两个市场同时发生**：Google 8t/8i（2026-04）、华为 950PR/950DT（2026）、NVIDIA（虽未拆分但 B6 判定 prefill/decode 分池）。**"按 workload 形态拆芯片"已在 2026 成为主流做法，而不是特例。** → 与 `B6` 的"推理专用硅"命题同源，与 `B7` 的华为产品线拆分完全同构。
2. **★ 8i 把片上 SRAM 提到 384 MB——Google 的推理芯片也在往"片上大存储"走。** 这与 `B6` 判定的 Groq LPU / Cerebras / Taalas 路线是同一个方向。**Google 是唯一同时拥有 OCS + 自研编译器 + 自研模型的玩家**（`B5` 已判定 OCS 是真正的 scale-up 绕开者）。

### §2.5 Anthropic · NKI kernel：模型公司写到了硅的寄存器层

【产业媒体·LinkedIn 技术长文 + Klover 分析，需交叉】：
- **Anthropic 用 >100 万颗 Trainium2（Project Rainier）跑 Claude，全部自定义 NKI kernel**；Anthropic 工程师**开发底层 kernel 直接对接 Trainium 硅，并贡献回 AWS Neuron 栈**，与 Annapurna 芯片设计团队紧密合作。
- **★ 计算模型与 GPU 根本不同**：**没有 warp、没有 thread、没有 syncthreads**。每个 NeuronCore-v4 有 4 个并行引擎（Tensor Engine 128×128 systolic array / Vector Engine / Scalar Engine / GPSIMD 跑自定义 C/C++）。**跨引擎流水线，而不是跨线程。**
- **★ 一个具体后果**：FlashAttention 之所以存在，是因为 GPU SRAM 装不下 N×N 注意力矩阵，只能 64–128 token 一 tile 做 online softmax；**在 Trainium3 上，attention kernel 每 tile 处理 2048 KV token**——4K 上下文只需 2 个外层 tile（GPU 上 32+）。
- **★ SBUF 容量悬崖**：每 NeuronCore 32 MiB 片上 scratchpad；**96% 利用率 = 29 MB spill 流量；99% = 931 MB**——**只因 3% 的利用率增加，HBM 流量涨 32×**（从 ~10 TB/s SBUF 带宽掉到 2.9 TB/s HBM）。**"这是一道悬崖，不是斜坡，且除了 profiling 没有任何预警。"**
- **★ 最重要的战略动作**：Anthropic **$650 亿 Series H 轮的投资方名单里包含 Micron、Samsung、SK hynix**——**把三家 HBM 制造商直接放进股东表**。Klover 的解读：**"通过把内存制造商直接放进资本表，Anthropic 把自己垂直整合到稀缺内存元件队伍的最前排，对冲半导体供应链深处的硬件瓶颈。"**
  → **这是 A 线玩家对 `B3` 判定"HBM 是 2027 最硬瓶颈"的直接金融对冲。**

⚠ 可靠性标注：Trainium 相关细节（NKI、SBUF 悬崖、Trainium3 tile 尺寸）来自单一 LinkedIn 技术长文与聚合站，**未见 AWS 官方文档**，列入待验证。

### §2.6 Meta · MTIA：唯一把"模型架构"直接写进芯片规格的

- 2026-03-11 发布四代：**MTIA 300 / 400 / 450 / 500**；**模块化 chiplet 设计，约 6 个月迭代一次**（远快于传统 GPU 周期）；MTIA 100/200 已生产部署**数十万颗**（ranking/recommendation）；最新代号 **Iris** 2026-09 投产；**MTIA v4（Cypress）已在 TSMC 2nm GAA 流片**。
- **2026-04-14 与 Broadcom 扩大合作至至少 2029**；Meta 算力 2026 年 **7 GW → 2027 年 14 GW**。
- **★ 最关键的一条**：**MTIA 450/500 引入专门面向 MoE 架构的 MX4 FLOPS**——原文表述："**MoE 是竞争硅厂商常当作 edge case 处理的范式**"。
  → **这是"模型架构定义芯片规格"最直白的一条证据**：Meta 因为自己的模型是 MoE，就在硅里为 MoE 单独留了算力单元。

**★ 2026-10-15 补充（接缝①的两个新证据）**：
1. **Anthropic × 三星深度谈判定制推理芯片**（2026-10，产业媒体）：合作范围是**架构定义 + 工艺（2nm 级）+ HBM 集成**的全面定制，不只是代工。→ 与 §2.5"把 HBM 三巨头放进股东表"构成**对偶动作**：Anthropic 对 HBM 缺口的对冲一手是股权（Micron/Samsung/SK hynix 进 Series H），一手是**直接与制造商共同定义芯片**。若谈成，接缝①就从"模型公司适应硅"变成"模型公司与存储厂商共同定义硅"。

## §3 接缝②：芯片反向塑造模型架构（B→A）

**★ 2026 年的状态被一句话概括**：【产业媒体·Wei's Learning Notes 汇总】**"行业已进入 Inference-Aware Architectures（推理感知架构）时代——模型在预训练阶段就被设计为适配低精度硬件与超大上下文。"**

这不只是一个说法，它有三个可验证的具体机制：

### §3.1 三个被硅逼出来的架构选择

| 机制 | 削减量级 | 采用方 | 由什么硅约束逼出 |
|---|---|---|---|
| **MLA**（Multi-head Latent Attention） | KV cache 比 GQA 减少 **4–6×**（低秩联合压缩 K/V 到潜向量） | DeepSeek-V3 系列、**Qwen-Reasoning**、**Kimi K3 的 Gated MLA**；SGLang 原生支持 | **HBM 容量/带宽**（`B3`） |
| **MTP / Self-Speculation** | 训练时带 MTP head，一次前向预测 k 个 token，**省掉独立 draft model 的 I/O 开销** | DeepSeek-V3、**Qwen3**；证据显示 GPT-4o/GPT-5 也已转向原生 MTP head | **decode 的带宽墙 + 单步延迟** |
| **FP4 / NVFP4** | 相对 FP8/FP16 **2–4× 吞吐**；比 INT4 更好地处理激活动态范围 | **Llama 4**、FLUX.1 原生 FP4 权重；**Kimi K3 训练用 MXFP4（权重）+ MXFP8（激活）** | **Blackwell 原生 FP4**（`B1`） |

### §3.2 ★ 一个反直觉的发现：瓶颈不是被消除，而是被**分化**

【一手三方·中兴通讯技术论文，2026-04】《新架构大模型推理的存算特征演变与近存计算适配技术研究》——这是本轮**方法论价值最高的一个来源**，因为它站在硬件侧描述模型侧的变化：

> 以 **DeepSeek-V4** 为代表的新一代 MoE 模型融合 **CSA（压缩稀疏注意力）+ HCA（高度压缩注意力）+ MTP**，把百万级超长上下文变成推理标配。**"该类架构并非简单消除 KV 缓存压力，而是将瓶颈进一步分化"**：
> - 长序列下原始 KV 被压缩块替代，**有效降低原生 KV 容量**，但**引入压缩索引、块元数据、稀疏检索计算等新开销**；
> - 万亿级总参 MoE 的**专家集合进一步扩张**，**FP4 混合量化成为权重部署主流**——**group-wise 缩放因子与路由索引的元数据访存占比持续抬升**。

**由此提出的三条硬件适配需求（即模型反过来给硅出的新题）：**
1. 近存单元不仅要处理原始 KV，还要支持**压缩 KV 块的原位检索、块筛选、索引遍历**——**硬件需同时兼容"稠密潜变量"与"稀疏压缩块"两套缓存访问范式**；
2. FP4 超低位宽下，近存通路需**原生兼容 Scale 元数据的并行加载与快速解包**——**缓解元数据流量对理论带宽收益的侵蚀**；
3. **MTP 改变单步 token 的算子调用模式**，专家层与注意力层的计算-访存交织关系更复杂，**固定流水线的近存硬件容易出现利用率下降**。

**★ 论文的核心结论（本文件认为这是 B→A 方向最精确的一句话）**：
> **"大模型推理的存算瓶颈正在从传统 MHA 注意力层，迁移至 MLA 潜变量缓存、压缩式长上下文 KV 块访问与 MoE 专家权重访问共同主导的新格局。"**

**→ 对本课题的意义**：`B6` 判定"推理专用硅靠绕开 HBM 形成护城河"，`B3` 判定"HBM 是 2027 最硬瓶颈"。**这条论文说明：即便 HBM 被绕开，瓶颈也不会消失，而是迁移到元数据访存与压缩索引检索上——一个目前"硬件加速缺失"的环节。** → **"绕开 HBM"不等于"绕开内存墙"。**

**同时它点出近存/存算一体的三条现存短板**：软件栈与编译器支持不足、低精度量化误差控制、MoE 路由预测不确定性、**压缩注意力索引检索的硬件加速缺失**（→ 与 `B7` §4.3 的字节×昕原 RRAM 路线直接相关：这条路要解决的就是这些）。

### §3.3 一个正在成形的第三条内存路：UMA / CXL

【产业媒体】**Universal Memory Architecture（UMA）**：主流硅厂商正采用 **CXL 2.0** 一致性互连，把 **DRAM / HBM / 持久内存统一到单一地址空间**，**13B 模型每 token 延迟降低最多 40%**。
另：近存计算的 MoE 分层方案——**热专家 HBM 常驻 / 冷专家近存执行 / 路由预测预取**，与 **CXL/DRAM 扩展层**协同。

→ **这是 `B5`、`B8`、`B3` 三次指向 CXL 之后，第一次在模型侧看到它的收益数字。**

**2026-10-15 更新**：该观察线已开——**`C1-CXL与UMA.md`**（含本条 13B −40% 的记录、CXL 4.0 vs 2.0 的启用率口径、以及 G3.5=L3.5 的 KV 中间层结论）。本节只保留结论指针，细节以 `C1` 为准。另：**"上架 ≠ 在用"** 的校准在 `C2`（71.4% 上架率 vs 约 30% 实际利用率）。

### §4.1 ★ TileLang：本轮对 CUDA 最可信的一次挑战，且它不在美国

- **核心设计**：北大 Wang et al.（2025-04 论文，ICLR 2026 oral）——**把调度空间与数据流解耦**：开发者指定"算什么"，编译器处理"怎么调度与同步"。单位是 **tile** 而非 thread。
- **生产验证**：DeepSeek V4 技术报告称 TileLang **替代了训练管线中"数百个细粒度 Torch ATen 算子中的绝大多数"**。
- **★ 硬数字（Ascend 950，CANN 9.20）**：
  - **DeepGEMM-Ascend：BF16 稠密 GEMM 达硬件上限 99.8%；FP8 约 99.5%**
  - **FlashMLA（V4.1）：prefill 410 TFLOPS（95%）、decode 360 TFLOPS（83%）**
  - **DeepEP-Ascend：≤32 设备 EP 组持续分发带宽达物理载荷上限 90–95%**（更大规模仍在优化）
  - DeepSeek 与华为**联合优化 128 芯片 Ascend 950 超节点**（计算 + 通信）
- 生态侧：华为升级 Ascend C、**进一步开放 PTO 指令架构**；CANN 转向社区驱动开源；昇腾已适配 **90+ 主要第三方开源项目**。

### §4.2 ★★ 一个必须写下的冲突：99.8% 与 55–65% 之间隔着一个"系统债"

`B7` 记录的结论是：**全链路国产集群的有效算力产出仅为海外方案的 55–65%**（十万卡/千亿参数训练：海外约 12 天 vs 国产 18–21 天）。
本节记录的结论是：**DeepGEMM 在 Ascend 950DT 上跑到硬件理论上限的 99.8%。**

**这两个数字不矛盾，但它们的差距本身就是一条结论：**

> **昇腾上的单个大算子已经能跑到硬件上限，但全链路训练效率只有 H100 的 55–65%。→ 损失不在算子，在算子之外：通信、调度、内存层次、并行策略、故障恢复。**
>
> **★ 换成本课题的术语：国产软件栈的「算子债」已经基本还清，「系统债」还没还。**
> **→ 这解释了 `B7` 那个"解药是厂商驻场"的现象**：驻场调的不是算子，是系统。
> **→ 也修正了 `B8` 的一个隐含假设**：B8 把"软件栈"当作一层来谈收益，本节说明它内部要再分——**算子层（已被 TileLang/CANN 基本解决）与系统层（通信/调度/并行，仍是主要损失来源）**。

⚠ **口径警告**（触发「模拟·论文≠生产」的同族检查）：99.8% 是**单算子微基准**，55–65% 是**端到端集群训练**。**两者不可换算，只并列。**

**同时并列 `B7` 与本节的两处规格冲突**：Ascend 950PR 带宽 **1.4 TB/s**（B7）vs **1.6 TB/s**（本节）；950DT 内存 **真 HBM**（B7）vs **HiZQ 2.0 / 144GB / 4.0 TB/s**（本节）。→ 待验证。

### §4.3 判断：控制权落在"谁能定义中间层"

> **CUDA 的护城河一直被描述为"算子生态 + 400 万开发者"。但 2026 年的事实是：算子这一层正在被商品化**（TileLang 证明单代码库可同时喂四个后端，CANN 证明 Triton/TileLang 可 100% 兼容）。
> **真正的争夺已经上移到"谁能定义中间表示与布局代数"**——OpenAI 发明 Linear Layouts、DeepSeek 生产化 TileLang 的调度/数据流解耦、Google 的 XLA+Pallas 双管。**谁定义 IR 与布局，谁就决定硬件是否可替换。**
> **→ 与 `B8` 的合并结论**：B8 判定"软件栈的经济作用是夺回'买什么芯片'的决策权"。本节补上机制：**夺回决策权的具体工具，是中间层（IR / 布局代数 / DSL），不是算子库。**

## §6 接缝⑤：单位经济闭环——一切收敛到"每兆瓦多少 token"

**★ 决定性事实**：【一手三方·SemiAnalysis InferenceX】**同一模型（DeepSeek-V4-Pro）、同一架构（Blackwell）、同一交互速度（27 tok/s/user）：**
- GB200 NVL72：**$0.28 / 百万 token**
- GB300 NVL72：**$0.12 / 百万 token** → **一代硅 −57%**

**但软件在同一块硅上的差距远大于此：**
- **同一台 GB300 机架跑 DeepSeek R1：MTP 关闭 = $2.35 / 百万 token；MTP 开启 = $0.11** → **21× 摆动**（150 tok/s/user）
- **"峰值 FLOPs 从未改变。账单变了。"**

**★ 由此得出的本层核心判断**：
> **MTP 是 2026 年推理成本的第一大杠杆，超过任何一代硬件跃迁。**（InferenceX：70–140 tok/s/user 区间约 **3×** 吞吐增益，低 batch 最强）
> **独立基准显示：在相同硅上，仅软件差异就造成每百万 token 成本 20 倍价差。**
> **→ 决定数据中心真实利润率的数字是 tokens per megawatt，不是峰值 FLOPs。**

**★ 2026-10-15 更新（本层最重要的一条新证据）**：微软 **Maia 300**（2026-10-12 发布，OCP）**把"每瓦电力、每美元投入所能产生的有效 Token 数量"写进官方头条规格，自报每兆瓦 Token 比领先 GPU 系统高 40%**——**这是结算框架的语言第一次成为厂商营销语言**：变量①（每兆瓦 token 数）从分析工具变成厂商主动填报的口径。→ ✅ **2026-10-16 C4 已开线并结案**：由此立**第八类口径错误「自报 ≠ 可比」**——各家自报的 +40%（Maia）／50×（NVIDIA GB300 tok/s/MW）／1.5–1.9×（Jalapeño per kW）分母与测试条件各不相同（封装 TDP / all-in 设施功耗 / 相似延迟约束 / 预测租价四种分母，Jalapeño 的 700 W 与 1.18 kW 差 1.7×），**自报口径之间不可直接换算，只能按测试条件分栏并列**。完整版见 `C4-每兆瓦Token厂商口径.md`，回写见 `00` §5.3.1。

## §7 ★★ 与 `B8` 的正面冲突：OpenAI 在 Jalapeño 上**不做** prefill-decode 解耦

这是本轮**最具冲突价值**的一条发现，必须完整记录。

`B8` 的核心结论之一是解耦（PDD）的价值：DeepSeek 4:18、EP32 vs EP144、+75%/+525% 来自整套解耦栈，四个阈值。

**但 OpenAI 在 Jalapeño 上明确选择不做 PDD**，SemiAnalysis 表示意外（"NVIDIA 与 AMD GPU 即便在同构硬件上也从 PDD 获益显著"）。理由原文：

> "**当 workload 被冻结时，PDD 看起来很划算。** prefill 与 decode 对硬件的压力不同，把每个阶段分给单独调优的池，可以在某个选定的输入/输出比例上提升效率。**但生产流量不会停在这个比例上。** 输入与输出序列长度、并发、缓存命中率、投机接受率、延迟目标全天都在动。
> **一旦把设备分成 prefill 池与 decode 池：prefill 需求过多 → decode 芯片闲置而请求排队；decode 需求过多则相反。** 运营方必须持续预测正确的切分、两边都预留冗余、并不断再平衡一个理想比例永远在移动的系统。
> **在统一系统里，某些资源可能在某个阶段被低用，但每台设备都能服务下一个请求。在解耦系统里，整颗芯片可能仅仅因为属于错误的池而闲置。局部利用率看起来更好，全局利用率可能很差。**"
> **且：解耦还会破坏局部性（locality）。**

**★ 这不是"谁对谁错"，这是两个不同的优化目标，必须并列：**

| | `B8` 的解耦派 | OpenAI 的统一派 |
|---|---|---|
| 硬件前提 | 同构 GPU 机队，跨机架 RDMA | **Jalapeño 局部域 128 XPU，KV cache 常驻域内** |
| 优化目标 | **延迟可控**（vLLM 官方：解耦**不提升吞吐**） | **全局利用率**（避免整芯片因"属于错误的池"而闲置） |
| 流量假设 | 可切分、比例相对稳定 | **生产流量比例全天在动** |
| 关键代价 | 需持续预测切分 + 双边冗余 + 再平衡 | 单阶段内可能有资源低用 |

**→ 合并判断（本文件提出）**：
> **解耦与否不是一个普适结论，而是一个"局部域有多大 + KV 能不能留在域内"的函数。**
> - 当**局部域足够大**（Jalapeño 128 XPU / 27.5 TB HBM4；或 `B5` 的 Google OCS 9,216 芯片）**且 KV 能常驻域内**时，**统一池更优**（局部性保住了，切分问题消失了）；
> - 当**局部域小、KV 必须跨机架搬运**时，解耦才划算（因为它把搬运变成了可控的、批量的传输）。
>
> **→ 这条对 `B8` 是一个真正的修正**：B8 把解耦写成"有四个阈值的最佳实践"，本节说明**还有第五个条件：局部域规模**。而 `B5` 恰好提供了这个变量的度量——**域大小就是分界线，这也解释了为什么 B5 反复强调"分界线是域大小而不是技术偏好"。**

**⚠ 但必须并列 OpenAI 自己的 caveat**：初始基准是单轮 8k/1k 且**未启用 MTP**，长上下文、多轮、agentic 负载下的结论仍是开放问题。

## §8 与 `A-2` 的接口：交汇点比"自研芯片"更深的那层

`A2` §4.4 的推论是：**进步函数从"预训练算力"转向"环境交互吞吐"，因此管制从"卡训练"变形为"卡推理"。** `A2` 并说"这是 A 线和 B 线真正的接口，比'模型公司自研芯片'深一层"。

**本节给这条接口补上两条 2026 年的实证：**

1. **★ "AI 参与制造下一代 AI"已经可测量，且量级不小**：OpenAI 用 XLS + 自己的模型做 continuous convergence，**BF16 乘法 +56%**，**9 个月流片**；Richard Ho 说目标是"把硬件时间线拉近软件时间线"。Kimi K3 用 48 小时从零设计芯片。**→ 这两条合起来说明：芯片设计的迭代周期正在被 AI 压缩，而芯片迭代周期正是 `B6` 判定"硅片冻结 vs 模型迭代"冲突的那个时间常数。**
2. **★ 一条元观察（SemiAnalysis 的讽刺）**：跑在 NVIDIA GPU 上的 GPT 5.6 Sol，被用来设计威胁 CUDA 护城河的芯片。**→ 管制与护城河都在一个自我侵蚀的循环里：领先者的算力正被用于制造它的替代者。**

**→ 因此 `A-2` 的接口表述可再推一层**：
> **不只是"管制从卡训练变形为卡推理"，而是"卡推理"这件事本身正在被两股力量同时削弱**：① 软件栈把每一块硅的 token 产出拉开 20 倍（§6）——**买方可以用软件补硬件的不足**；② AI 把硅的设计周期从 18–24 个月压到 9 个月（§2.1）——**追赶者可以用速度补代差**。
> **→ 这两条都是 `A-2` 那句"进步函数换引擎"在产业层的投影。**

## §11 已确立的结论（供 `00` 回写）

1. **★ 交汇点确认为"双向锁定"，不是单向的"模型公司做芯片"。** 五个接缝：① 模型公司自研硅与编译器（A→B）② 芯片反向塑造模型架构（B→A）③ 编译器/DSL 层成为控制权落点（争夺）④ 芯片方反向进入模型层（B→A）⑤ 单位经济闭环（收敛）。题眼：**"models shaped by the silicon beneath them, silicon shaped by the models above them"**。
2. **★ OpenAI Jalapeño**：与 Broadcom 共同设计、TSMC 制造（3nm-class vs 2nm-class 两口径并列）、**从设计到流片 9 个月**（史上最快 ASIC 周期）；单芯片 **13.4 PFLOPS MXFP4 / 6×HBM4 216 GiB / 15.4 TB/s / 700W**；**局部域 128 XPU = 1.7 EFLOPS + 27.5 TB HBM4（KV 常驻域内）**，6,144 对差分**无源铜背板**；全局域 **2,048 芯片/16 机架/27 EFLOPS**，**Tomahawk 6 + 混合铜光 + OCS**；**每千瓦吞吐比 GB200/GB300 高 1.5–1.9×**；全系统 **1.18 kW vs GB300 2.55 kW**。
3. **★ AI 辅助设计已可测量**：XLS 硬件描述语言上的 "continuous convergence" 工作流，**BF16 乘法比人类工程基线 +56%**；Richard Ho：**不是"写代码-编译-测试"，而是派生成百上千 agent 夜间跑验证/时序收敛/面积优化**。→ **芯片设计周期正被 AI 压缩（18–24 个月 → 9 个月），而这正是 `B6` 判定"硅片冻结 vs 模型迭代"冲突的那个时间常数。**
4. **★ Gluon = 模型公司定义硬件抽象层的第一手物证**：建在 OpenAI 自己的 Triton 上，保留 SPMD 但暴露 PTX 级 MMA/TMA/mbarrier；核心抽象 **Layout** 由 **Linear Layouts**（OpenAI 发明并发表的**布局代数**，𝔽₂ 上的二元矩阵代数）形式化 → **可证明正确的布局转换 + 最优内存 swizzling**；每个 Gluon 程序映射到**持久线程**，**由程序员而非硬件调度器分配 tile**。配套 Codex 生成 kernel、**chilisim 模拟器精度 5% 以内**；迭代速度：2 周 2×、8 天 TP8→TP32。
5. **★ 战略定性（必须带）**：Jalapeño 是 **captive silicon、只做推理**，**不替代 NVIDIA**；训练继续依赖 NVIDIA（合作到 2030 年最高 $6,000 亿）。策略是"**在新模型/高量模型上部署 Jalapeño，用多供应商机队服务不同档位**"。⚠ caveat：基准为单轮 8k/1k、**未启用 MTP**，2027 量产时真正基线是 Vera Rubin。
6. **★ Kimi K3（官方）**：**MiniTriton** = 基于 MLIR 自建 tile 级 IR + 优化 Pass + **PTX codegen**，Roofline 达到或超过 Triton 与 torch.compile，**端到端 nanoGPT 训练稳定收敛**；芯片原型 48 小时自主运行（开源 EDA + Nangate 45nm），**4 mm² / 146 万标准单元 / 0.277 MB SRAM / INT4 MAC 带融合反量化 / 100MHz / >8,700 tok/s**，官方定性"**一颗由模型设计、为模型服务的芯片**"。**另：Moonshot 向 vLLM 社区贡献了 KDA prefill-cache 实现。** ⚠ 与 Jalapeño 相差约 6 个数量级应用层级，**不可比**。
7. **★ Google 是唯一把这条接缝跑了十年的**：Ironwood 9,216 芯片 / 42.5 EFLOPS / **1.77 PB 全局可寻址 HBM**（世界纪录）/ ICI 88,473.6 Tbps；**XLA（基线）+ Pallas（峰值）双管策略是官方表述的 co-design 基本原则**；**SparseCores 第四代卸载集合通信与主 TensorCore 完全并行**（"模型公司痛点被烧进硅"）。**★ TPU 8t/8i 拆分 = 与华为 950PR/950DT 同构——"按 workload 拆芯片"在 2026 已成主流做法**，且 **8i 把片上 SRAM 提到 384 MB**（与 `B6` 的 Groq/Cerebras 路线同向）。
8. **★ Anthropic 写到硅的寄存器层**：>100 万颗 Trainium2 跑 Claude，**全部自定义 NKI kernel**，并**贡献回 AWS Neuron 栈**；计算模型**无 warp/thread/syncthreads**，4 引擎流水线；**Trainium3 attention 每 tile 2048 KV token**（GPU 上 64–128）；**★ SBUF 容量悬崖：96% 利用率 = 29MB spill，99% = 931MB（3% 的利用率增加 → 32× HBM 流量）**。
9. **★ Anthropic 把 HBM 三巨头放进股东表**：$650 亿 Series H 含 **Micron / Samsung / SK hynix**——**A 线玩家对 `B3`"HBM 是 2027 最硬瓶颈"的直接金融对冲**。（二手，待确认。）
10. **★ Meta 是唯一把模型架构写进芯片规格的**：**MTIA 450/500 引入专门面向 MoE 的 MX4 FLOPS**，原文称"MoE 是竞争硅厂商常当作 edge case 处理的范式"；**约 6 个月迭代一次**（chiplet 模块化）、Iris 2026-09 投产、Cypress 已在 TSMC 2nm GAA 流片、Broadcom 合作至 2029。（多数细节为二手，待验证。）
11. **★ 2026 已进入 "Inference-Aware Architectures" 时代**：模型在**预训练阶段**就被设计为适配低精度硬件与超大上下文。三个机制：**MLA**（KV cache −4–6×）、**MTP/Self-Speculation**（省掉独立 draft model）、**FP4/NVFP4**（2–4× 吞吐；Llama 4 原生 FP4 权重、Kimi K3 训练用 MXFP4+MXFP8）。
12. **★★ 瓶颈不是被消除而是被分化**（中兴 2026-04 论文，本轮方法论价值最高的来源）：DeepSeek-V4 的 **CSA+HCA+MTP** 把原始 KV 换成压缩块，**降低原生 KV 容量但引入压缩索引/块元数据/稀疏检索等新开销**；**FP4 混合量化成权重部署主流，group-wise 缩放因子与路由索引的元数据访存占比持续抬升**。三条新硬件需求：① 兼容"稠密潜变量 + 稀疏压缩块"两套缓存访问范式 ② 原生支持 Scale 元数据并行加载与快速解包 ③ MTP 改变算子调用模式，固定流水线近存硬件易降利用率。→ **"大模型推理的存算瓶颈正从传统 MHA 注意力层，迁移到 MLA 潜变量缓存 + 压缩长上下文 KV 块访问 + MoE 专家权重访问共同主导的新格局。"** → **"绕开 HBM"不等于"绕开内存墙"。**
13. **★★ 一个新判断：国产软件栈的「算子债」已基本还清，「系统债」还没还。** DeepGEMM-Ascend 在 950DT 上达硬件上限 **99.8%**（FP8 99.5%）、FlashMLA 95%/83%、DeepEP ≤32 设备 90–95%；但 `B7` 记录全链路训练效率仅海外 **55–65%**。→ **损失不在算子，在算子之外（通信/调度/内存层次/并行策略/故障恢复）。这解释了 B7 的"解药是厂商驻场"——驻场调的不是算子，是系统。也修正了 `B8`：软件栈内部要再分为算子层（已基本解决）与系统层（仍是主要损失来源）。** ⚠ 99.8% 是单算子微基准，55–65% 是端到端集群，**不可换算，只并列**。
14. **★ TileLang = 二十年来对 CUDA 最可信的挑战，且它不在美国**：2026-09-30 开源六大模块，与 NVIDIA 版**一一对应**（改配置标志即可迁移）；**单代码库编译到 Ascend 950 / CUDA / ROCm / Metal**；北大发起、ICLR 2026 oral，**调度空间与数据流解耦**；V4 技术报告称**替代了训练管线中"数百个细粒度 Torch ATen 算子中的绝大多数"**；DeepSeek 与华为**联合优化 128 芯片 Ascend 950 超节点**；华为进一步**开放 PTO 指令架构**、昇腾已适配 90+ 第三方开源项目。
15. **★ 控制权的真正落点是"中间层"，不是算子库**：CUDA 的算子层正在被商品化（TileLang 一码四后端、CANN 对 Triton/TileLang 100% 兼容）。争夺已上移到 **IR 与布局代数**——OpenAI 发明 Linear Layouts、DeepSeek 生产化调度/数据流解耦、Google XLA+Pallas 双管。**谁定义 IR 与布局，谁决定硬件是否可替换。** → 这是 `B8`"软件栈夺回买芯片决策权"的具体机制。
16. **★ 芯片方反向进入模型层（本轮最意外的证据）**：【官方·NVIDIA Dynamo 文档】NVIDIA 为 **DeepSeek-V4、Kimi-K2.6、GLM-5.2、MiniMax-M3、Nemotron-3 系列、Cosmos-3、Inkling** 各开一条 release branch 并打 tag；治理方式是**一旦 patch upstream 到 vLLM/SGLang 就 promoted 到标准容器、dev image 退役**——**NVIDIA 在为整个生态（含对手模型）做上游化工作**。另：Nemotron 3 Super（Mamba-Transformer hybrid MoE、120B/12B、1M 上下文、**优化为单 GPU 跑多 agent**）= NVIDIA 自己定义"什么架构适合我的硅"；NVIDIA 已把推理经济学正式称为 **tokenomics**。
17. **★★ 与 `B8` 的正面冲突：OpenAI 在 Jalapeño 上不做 prefill-decode 解耦。** SemiAnalysis 表示意外。理由：生产流量的输入/输出比全天在动，一旦分池，"**整颗芯片可能仅仅因为属于错误的池而闲置；局部利用率看起来更好，全局利用率可能很差**"，且**解耦破坏局部性**。
    **→ 合并判断（对 `B8` 的修正）：解耦不是普适最佳实践，而是"局部域规模 + KV 能否留在域内"的函数。** 局部域足够大且 KV 常驻（Jalapeño 128 XPU/27.5 TB；Google OCS 9,216 芯片）→ **统一池更优**；局部域小、KV 必须跨机架搬 → 解耦才划算。**→ `B8` 的四个阈值要加第五个条件：局部域规模。而 `B5` 恰好提供了这个变量的度量（域大小就是分界线）。**
18. **★ 单位经济闭环：一切收敛到"每兆瓦多少 token"。** 同一模型同一架构同一交互速度：**GB200 $0.28/百万 token vs GB300 $0.12（一代硅 −57%）**；但**同一台 GB300 跑 DeepSeek R1，MTP 关 $2.35 vs 开 $0.11（21×）**——**"峰值 FLOPs 从未改变，账单变了。"** 独立基准：**相同硅上仅软件差异造成 20 倍价差**。→ **MTP 是 2026 年推理成本第一大杠杆，超过任何一代硬件跃迁。决定数据中心真实利润率的是 tokens per megawatt，不是峰值 FLOPs。**
19. **成本分解（乘法叠加）**：硅代际 −57% × 软件 MTP 21× × 量化约 5× × 连续批处理 2–4× × 提示缓存 −45~80% × MoE × MLA 4–6× × 利用率（22%→68% 案例，约 2.4×）→ 历史对照：2023 初 GPT-4 水平约 **$20/百万 token** → 2026 约 **$0.4（50×）**。市场：均价 2026-05 **$2.04** → 08 **$1.16**；前沿 API $7.50–15 / 开放模型 API $0.09–0.60 / 自托管 $0.30–0.60；自托管决策边界约 1 亿 token/月。**→ 与 `A1b` 合并：中国厂商低价里"工程效率"那一半，主要是软件栈与利用率，不是硅。**
20. **MLPerf v6.0（审计口径）**：Blackwell Ultra vs Blackwell（DeepSeek-R1）Offline **+45%** / Server **+25%**；NVIDIA 首个 288-GPU 提交 GPT-OSS-120B 聚合 **250 万 token/s**（软件单轮最多 +2.7×）；**AMD MI355X 87 GPU 首次破 100 万 token/s**（Llama 2 70B），落在 B300 的 **92–104%**，GLM-5 FP8+MTP **$0.22 vs B200 $0.30（便宜 27%）**。⚠ NVIDIA 的 15–35× 是机架级/基准特定/低延迟优化口径，普通团队在 13B–70B 上是两位数百分比而非数量级。
21. **★ 与 `A-2` 的接口再推一层**：不只是"管制从卡训练变形为卡推理"，而是**"卡推理"正被两股力量同时削弱**——① 软件把每块硅的 token 产出拉开 20 倍（买方可用软件补硬件不足）② AI 把硅设计周期从 18–24 个月压到 9 个月（追赶者可用速度补代差）。**且有一层自我侵蚀**：跑在 NVIDIA GPU 上的 GPT 5.6 Sol 被用来设计威胁 CUDA 护城河的芯片——**"NVIDIA 自己的 GPU 正在实时助推它的潜在继任者"。**
