# B5 · 互连与光

> **分析单位**：**域（domain）+ 转换点**，不是公司、不是产品。
> 本层只分三块：**scale-up 域**（机架内，加速器↔加速器）、**scale-out 域**（机架间，节点↔节点）、**光电转换点**（铜→光的物理边界）。同一家公司在不同域里角色完全不同（NVIDIA 在两个域都是第一，Broadcom 只在 scale-out，Amphenol 只在转换点左侧），**用"谁最强"框架会立刻失效**。

## §0 命题：B8 说"必须 RDMA"，B5 回答"RDMA 跑在谁的上头"

`B8` 的收口结论是：解耦有四个阈值，其中"**必须 RDMA，TCP 不成立**"把互连**从配套件推成了决策变量**。B5 承接的就是这一条。

但检索下来，B5 的命题比"互连有多重要"更具体：

> **B5 要回答的是：解耦所依赖的那条 RDMA 路径，其承载层的所有权归谁、成本由什么决定、以及有没有一条不付这笔钱的路。**

而这条路径上出现了一个此前未被写下的关键事实——

### ★ 本层第一发现：网络 attach rate 接近 90%，且**用自研芯片的客户仍在买 NVIDIA 的网络**

> 【官方·NVIDIA CFO Colette Kress，CES 2026】：
> ① 购买 NVIDIA AI 系统的客户中，**接近 90% 同时购买网络产品**（NVLink + InfiniBand + Spectrum-X）；
> ② **即使那些在部分部署中使用自研 AI 芯片的客户，通常仍在使用 NVIDIA 的网络技术。**

**这句话的分量超过本层任何一个带宽数字。** 它意味着：`B2` 里那六条云厂自研 ASIC 线（TPU / Trainium / Maia / MTIA / Jalapeño），即便在芯片层成功绕开 NVIDIA，**在网络层大概率仍在给 NVIDIA 付钱**。

**→ 与 `B8` 的合并结论：`B8` 说咽喉在传输层（NIXL），B5 说咽喉在传输层下面那层物理网络（Spectrum-X / NVLink），而且 **attach rate 90% + 自研芯片客户也买** —— 这两条合起来，才是"护城河迁移到互连"这个判断的完整证据链。**

## §1 三层分解表

| | **scale-up 域**（机架内） | **scale-out 域**（机架间） | **光电转换点** |
|---|---|---|---|
| **主要技术** | NVLink / UALink / ICI+OCS / Infinity Fabric / NeuronLink | 以太网（UEC）/ InfiniBand / 专有 DCN | 铜 DAC → 可插拔光模块 → NPO → CPO |

## §2 scale-up 域：NVLink 的"开放"，以及它埋的三条款

### 2.1 带宽与规模

| 代际 | 每 GPU 带宽 | 机架聚合 | 域规模 |
|---|---|---|---|
| NVLink 5（Blackwell B200） | **1.8 TB/s** | GB200 NVL72 **130 TB/s** | 72 GPU |
| NVLink 6（Vera Rubin，H2 2026 量产） | **3.6 TB/s** | NVL72 **260 TB/s** | 72（Kyber 提供 NVL72 / NVL144 / NVL576 三种） |
| NVLink 8（Feynman，2028） | 未披露 | — | **NVL1152**（8 个 Kyber 机架光互连） |

【官方·NVIDIA】NVIDIA 称 NVLink 1→6 每 GPU 带宽累计约 **58 倍**（⚠ NVLink 1 基线有 **62 GB/s** 与 **300 GB/s** 两种二手说法，待验证）。
对比：PCIe Gen5 上限约 **128 GB/s** —— NVLink 5 是它的 **14 倍**，这是张量并行可行的前提。

### 2.2 ★★ NVLink Fusion：一个"开放但必须买我一件东西"的设计

NVLink Fusion 于 Computex 2025（2026-05）发布、GTC 2026 大幅扩展。**表面是开放，实际有三条限制**（【一手三方·DigiTimes / ServeTheHome / IPNET 三家一致】）：

| 条款 | 内容 |
|---|---|
| **① 必须含一件 NVIDIA 产品** | 每个 NVLink Fusion 部署**必须至少包含一个 NVIDIA 产品**（GPU / CPU / NVLink 交换机 / ConnectX NIC）。**AMD 不能用它把 EPYC 直连 Instinct。** |
| **② 二选一** | 可以集成第三方 CPU **或** 第三方加速器，**但不能两者都是**——系统厂商无法构建"第三方 CPU + 第三方 GPU"的纯 NVLink 系统 |
| **③ 软件层不开放** | Alchip 可做**全栈硬件**实现，但**负责启动和配置链接的软件层仍由 NVIDIA 控制**；连接 NVSwitch 需**特殊许可**；NUMA、原子操作等高级协议层需**额外批准**。8 家伙伴中**只有 CPU 开发者（Marvell、Fujitsu）拿到硬件+软件全实现权**；Synopsys 等 IP 公司仅限 PHY + 链路层 |

> **DigiTimes 受访分析师的判断（值得整段引用）**：NVIDIA 在 AI 硬件领域的主导地位及其对**软件、定价和供应的垂直控制**，几乎没有激励去真正开放。**NVLink Fusion 看起来更像一场精心策划的努力**——在选定伙伴间维持商誉、以可控方式扩展 NVLink 生态、让寻求主权的客户能造自己的 CPU 或专用加速器，**同时降低 UALink 竞争平台的吸引力**。**NVLink 不是开放标准。**

### 2.3 ★ 最惊人的证据：AWS Trainium4 要插进 NVIDIA 的机架

| 事实 | 出处 |
|---|---|
| **AWS Trainium4**（re:Invent 2025 发布）**通过 UCIe 桥接芯片组接入 NVLink 6**，最多 72 颗 Trainium4 全互连 @3.6 TB/s | 【一手三方】 |
| **AWS 正把 Trainium4 集成进 NVIDIA 的 MGX 机架架构** | 【一手三方·NVIDIA】 |
| NVIDIA **2026-03-31 投资 Marvell $20 亿**——Marvell 是 AWS / Google / Microsoft 的 ASIC 设计方，与 Broadcom 并列两大定制 ASIC 设计公司 | 【官方·NVIDIA / Tom's Hardware】 |
| NVIDIA 予 **MediaTek $35 亿可转债**投资，换取其采用 NVLink Fusion | 【一手三方】 |
| NVIDIA **2026-03 各投 Lumentum 与 Coherent $20 亿**（合计 $40 亿）+ 多年采购承诺，锁定激光器与光学元件优先供应 | 【官方·NVIDIA】 |

> **→ 与 `B2` 的正面冲突（本层最锋利的一条）**：`B2` 的整条叙事是"云厂自研 ASIC 是为了摆脱对 NVIDIA 的依赖"。而 2026 年的事实是：**Trainium4 插在 NVIDIA 的 MGX 机架里、走 NVLink 6；给 AWS 设计这颗芯片的 Marvell 刚拿了 NVIDIA 的 $20 亿。**
> **→ 这不是"ASIC 替代 GPU"，而是"ASIC 在 NVIDIA 的机架里做增量"。** NVIDIA 用开放的 NVLink Fusion + 三笔投资（Marvell / MediaTek / Lumentum+Coherent）**把对手的供应链变成了自己的生态入口。**
> **→ 一句话：NVLink Fusion 的设计目的不是赚钱，是让每一台非 NVIDIA 的机架都还得装一件 NVIDIA 的东西。**

## §3 ★ 真正绕开 scale-up 护城河的不是 UALink，是 Google 的 OCS

这是本轮检索中最反直觉、也最有价值的一条。

### 3.1 三种完全不同的"光"

| 路线 | 做法 | 谁在推 | 状态 |
|---|---|---|---|
| **CPO**（共封装光学） | 把光引擎放到交换芯片旁边，缩短电路径 | NVIDIA（Spectrum-X CPO，TSMC COUPE）、Broadcom（Bailly / Tomahawk 6 Davisson） | 小批量出货；**黄仁勋 GTC 2026-03 亲口说大规模落地推迟到 2028 Feynman** |
| **NPO**（近封装光学） | 折中：光引擎在封装近旁但不共封装 | **华为 2026-07 联合百度、京东云、中国移动研究院等 20+ 企业发起国内首个 OPEN NPO MSA**；Arista 牵头 **XPO 标准联盟**（12.8T） | 标准形成期 |
| **OCS**（光路交换） | **交换本身做成光的**：MEMS 微镜重构拓扑，**不做光电光转换** | **Google（Apollo）** | **已在跑** |

### 3.2 Google Ironwood 的实际规模（这是全行业最大的全光算力矩阵）

【官方·Google Cloud Blog】+【一手三方】：

| 项 | 数值 |
|---|---|
| 拓扑 | 每主机 4 颗 TPU；**每机架 64 颗 = 1 个 cube**，cube 内 ICI 构成 **3D Torus**；每颗芯片连 6 颗其他芯片、提供 3 个并行轴 |
| 扩展 | **cube 之间用 OCS 光交换网络互连**；256 芯片 = 1 pod（4 cube）；**9,216 芯片 = 1 superpod（144 cube）**；再往上走标准 DCN |
| 带宽 | ICI **9.6 Tbps**；superpod 总互连 **88,473.6 Tbps（11,059.2 TB/s）** |
| 内存 | 每芯片 8 堆叠 HBM3E、**192 GiB、7.4 TB/s**；superpod 可同时访问 **1.77 PB HBM** |
| 算力 | **42.5 ExaFLOPS FP8**（对比：El Capitan 1.7 EF） |
| 能效 | perf/watt **2× Trillium**；比 2018 年首款 Cloud TPU 高约 **30×** |
| **容错（OCS 的核心价值）** | cube 或链路故障时，OCS fabric manager 指令 OCS **在毫秒级绕过故障单元并接入备件**；液冷 TPU 机队自 2020 年起维持 **99.999% 可用性** |

**Google Apollo OCS 相对传统电交换的实测**：吞吐 **+30%**、功耗 **−40%**、**波特率无关（baud-rate independence）**——即 OCS 一次性投入可适配未来 1.6T 乃至更高速率，**不必随速率换代**。
另一组对照口径：OCS 方案 vs 传统电交换——单集群算力 42.5 vs 3–5 EF；互连规模 9,216 卡 vs 通常不超过千卡；训练吞吐 +30%；任务完成时间 −10%；可用性 99.999% vs 99.9%。【产业媒体·中文，需交叉】

**已切换规模**：Google 已在 TPU v5p 集群完成全面切换，**2026 年计划在 26 个超算集群 all-in OCS**。
**中国政策已跟进**：**工信部 2026-04-02《普惠算力赋能中小企业专项行动方案》明确提出推动全光交换技术应用部署。**

### 3.3 ★ 为什么这条重要：它给了 B8 一个完全不同的答案

`B8` §4 的收口是"传输层是咽喉，NVIDIA 用 NIXL 控制它"。B5 现在要补的是：

> **Google 是唯一一个在 B2（TPU 芯片）、B5（OCS 网络）、B8（Raiden 传输层 + TurboQuant KV 压缩）三层都有独立方案的公司。**
> **NVIDIA 是唯一一个在 B1（GPU）、B5（NVLink + Spectrum-X）、B8（NIXL + Dynamo）三层都有控制的公司。**
> **→ 这一层的主命题就是这两个垂直整合巨头的对撞，而且它们在每一层都选了相反的技术路线：**

| 层 | NVIDIA 的选择 | Google 的选择 |
|---|---|---|
| scale-up | **专有铜互连（NVLink）**，到 1152 才转光 | **光交换（OCS）+ 3D Torus**，从一开始就是光的 |
| scale-out | Spectrum-X 以太网 / InfiniBand | 标准 DCN + OCS 切分 slice |
| 传输层 | **NIXL**（已成 vLLM 默认） | **Raiden**（Apache-2.0，自述未投产） |
| 缓存层 | Dynamo 多层 KV 管理 | **TurboQuant 3.5bit 压缩**（论文，未开源） |

**→ 判断：Google 的 OCS 路线在"绕开 NVIDIA scale-up 护城河"这件事上，比 UALink 有效得多——因为它已经跑起来了，而 UALink 的第一款交换机还在等 Marvell。** 但 OCS 目前**是 Google 内部的**，不外售，也不被 vLLM/SGLang 生态感知——**它的外溢路径和 Raiden 一样，都卡在"能否成为公共生态的一部分"。**

- 核心机制 **UET** 取代 RoCEv2：从"流级 ECMP 哈希"改为**逐包多路径喷洒（packet spraying）**，原生支持乱序可靠投递；丢包恢复从 Go-Back-N 改为**逐包选择性重传**；目标 **100 万+ 端点**

> **判断**：UEC 的技术规格已经完备、互操作验证已过。**它缺的不是规格，是"谁第一个大规模部署"。** 对比 UALink 卡在交换机供应链、NVLink 卡在"必须买一件 NVIDIA 产品"——**三条路各自的瓶颈性质完全不同**（规格 / 供应链 / 许可条款）。

## §5 光电转换点：不是"光进铜退"，是域大小决定分工

### 5.1 ★ 黄仁勋亲自纠正了市场叙事

> 【官方·黄仁勋 GTC 2026】"**我们需要更多的铜缆、更多的光模块、更多的 CPO 产能。**"
> 【官方·黄仁勋 2025-08 对台媒】"**我们应该尽可能久地留在铜上**（stay with copper for as long as we can）"；只有"**如果必须**"时才转硅光——**不是因为光更优，而是因为铜在距离和速率上会到头。**
> 【官方·NVIDIA 网络 SVP Gilad Shainer，GTC 2026】铜是**无源的**、功耗接近于零、**没有有源器件可失效**。**只要距离允许就用铜，句号。** 决定因素是**域大小**：NVL72 / NVL144 在铜的可达范围内 → 用铜；到 NVL1152 跨机架 → 超出无源铜能力 → CPO 接手。

**→ 这意味着"光进铜退"是一个被市场误造的叙事。** 正确表述是：**铜与光按域分工，机柜内铜主导至少到 2027，机柜内光的大规模渗透要等 2028 Feynman 平台。**

| 场景 | 介质 | 时间 |
|---|---|---|
| 机架内（scale-up） | **铜主导** | **2026–2027 确定**；光替代推迟至 2028 Feynman |
| 机架间（scale-out） | **光主导** | 已经，**渗透 >80%** |

### 5.2 物理边界的具体数字

| 项 | 数值 | 出处 |
|---|---|---|
| 200 Gbps/lane 下无源铜 reach | **约 1 米** | 【一手三方】 |
| NVLink 6 定义 | **400G SerDes/lane**，峰值 3.6 TB/s/GPU → 电信号随距离快速衰减，铜互连限 **<1 米** | 【一手三方·TrendForce】 |
| 铜 vs 光成本 | 机架内无源铜每比特比光收发器便宜 **5–10 倍** | 【官方·NVIDIA】 |
| GB200 NVL72 机架内铜缆 | **约 2 英里**（黄仁勋）；另源称单台 NVL72 约 **5,000 根** NVLink 铜缆、连接器用量达万级，单 GPU 对应高速连接器需求比前代 DGX **跳升 5 倍** | 【官方】/【产业媒体】 |

### 7.3 FCC 草案：三个关键限定 + 一个致命模糊点

| 限定 | 内容 |
|---|---|
| ① **只针对新型号** | 已获 FCC 设备授权的存量型号可继续在美销售（含在售 800G 及已认证版 1.6T）。**冲击的是"未来新品"，不是"现有收入"** |

- 中际旭创 **2026 Q1 海外产能出货占比已达 84.87%**，海外产能利用率 87.3%

> **→ B7 在这一层的正确问题不是"国产能否替代"，而是"美国能否脱钩"，以及"上游 DSP/激光器/InP 衬底才是中国真正的缺口"。**

## §8 ★ 与 B8 的经济闭环：KV 传输有三条路，成本差 1–2 个数量级

这是 B5 与 B8 连读后浮现的、两边都没单独说出来的结论。

`B8` 讨论 KV 缓存传输时只处理了两条路径（NVLink / RDMA 以太网），并给出"必须 RDMA"的阈值。B5 现在给出第三条：

| 路径 | 介质 | 成本量级 | 性能损失 | 出处 |
|---|---|---|---|---|
| **① scale-up（机架内）** | 铜 NVLink | **几乎免费**（铜每比特比光便宜 5–10×） | 无 | §5.2 |
| **② scale-out（跨机架）** | 光模块 + RDMA | **1.6T 模块 ~$1,200/只；800G ~$390/只** | 无 | §5.3 |
| **③ 存储层（NVMe-oF / CXL）** | 共享存储 | **Xinnor 实测：远端 NVMe-oF 与本地 NVMe 性能相同（都是 1.52×）** | **无——共享不花代价** | `B8` §5.1 |

**关键推理**：
- `B8` 已证明 **DeepSeek 生产实测 56.3% 的输入 token 命中盘上 KV 缓存**——即**超过一半的 KV 根本没走网络，而是走存储层**。
- `B8` §5.1 的 Xinnor 实测又证明**走远端存储（NVMe-oF）与走本地存储性能完全相同**。
- **→ 因此"KV 走网络还是走存储"在物理上没有性能差异，是一个纯成本决策。而成本差 1–2 个数量级（光模块每只 $1,200 vs 存储摊薄）。**

> **★ 结论：解耦的 KV 传输成本可以通过"降级到存储层"被大幅压缩，而这在物理上不损失性能。**
> **→ 这给 `B8` 补上了它缺的那一半**：B8 说"传输层是咽喉（NIXL）"，B5 说"**但咽喉可以被绕过——把 KV 从网络上挪到存储上**"。而 `B8` §5.2 判定的 CXL（TraCT 用 CXL 共享内存替代 RDMA，TTFT −2.6× / P99 −3.0× / goodput +1.9×）正是这条绕行路的硬件形态。
> **→ 这也解释了为什么 NVIDIA 在 2026-08-04 要开放 cuFile API 与存储栈**：**如果 KV 走存储，传输层的控制权就丢了。开放存储栈是为了让 KV 走存储时也还在自己的栈里。** 【这条推断为本文件提出，未见他处明说，标为推论】

**另一条成本侧的新事实**：`B8` 没有给解耦算过光模块钱。现在可以算了——**跨机架解耦的每个 KV 传输都要付 scale-out 的钱**，而 1.6T 模块 $1,200/只、且**有效产能只能满足约 60–80% 的需求**（§5.3）。**→ 解耦的规模扩张，在 2026–2027 会直接撞上 1.6T 光模块的产能墙。这是 B8 的"16–32 卡阈值"之外，第二个规模约束，而且它是供给侧的。**

## §9 与其他线的接缝与冲突

### 9.1 对 `B8`（最直接）
- **B8 的"必须 RDMA"落在 B5 的 scale-out 域**，成本锚点 = 1.6T 模块 $1,200/只。
- **★ 补上 B8 缺的第三条 KV 路径（存储层）**，并指出"走存储不损失性能"已有实测。→ **咽喉可被绕过。**
- **CXL 同时是 B8 的绕行路与 B5 的 scale-up 替代路线**（Marvell 的 XConn 资产同时做 UALink 交换机和 CXL 交换机）。
- **NVIDIA 开放 cuFile 的动机**（推论）：防止 KV 走存储时脱离自己的栈。

### 9.2 对 `B2`（正面冲突）
- **★ AWS Trainium4 集成进 NVIDIA MGX 机架、走 NVLink 6**；**Marvell（AWS/Google/Microsoft 的 ASIC 设计方）拿了 NVIDIA $20 亿投资**。
- **→ `B2` 的"自研 ASIC = 摆脱 NVIDIA"叙事，在 2026 年已被部分证伪：至少在机架与互连层，ASIC 仍在 NVIDIA 的系统里。** 但 `B2` 的"自用口径 ASP 溢价永久成立"不受影响——**因为 Trainium4 依然是自用的，它只是自用在 NVIDIA 的机架里。两条结论可以并存，但必须同时陈述。**

### 9.3 对 `B1`
- **网络收入独立成线得到 SEC 口径确认**：FY2026 网络 $313.76 亿（+141.5%）vs 算力 +58.9%，占 DC 11.3%→16.2%。⚠ 与 B1 的"~12%→~20%"口径冲突，待核。

- **护城河三段落点再补一条**：CUDA 算子 → 每 GW 打包值 → KV 传输层（NIXL）→ **"至少一个 NVIDIA 产品"的许可条款（NVLink Fusion）**。**第四条是唯一一条写进合同条款里的。**

### 9.4 对 `B3`
- **CPO 交换机要与 AI 加速器抢同一批 2.5D/3D 先进封装产能** → `B3` 的 CoWoS 约束多了一个需求方。

### 9.5 对 `B6`
- **Groq LPU 不走 NVLink Fusion** —— 它通过以太网背板（NVIDIA 称之为 **Oberon ETL256**）连接 Vera Rubin，**由 Dynamo 软件编排 GPU-LPU 分工**（Ian Buck 在 GTC 2026 记者问答确认）。

### 9.6 对 `B7`
- **光模块这一层中国在 800G/1.6T 占 65–70%、Top10 占 7 席** → B7 在这一层的命题应反转为"美国能否脱钩"，且真正的缺口在**上游 DSP / 激光器 / InP 衬底**。

## §12 B5 已确立的结论（供 `00` 回写）

1. **★ 本层第一发现：NVIDIA 网络 attach rate 接近 90%，且"即使部分部署使用自研 AI 芯片的客户，通常仍在使用 NVIDIA 的网络技术"**（CFO Colette Kress，CES 2026）。→ **B2 的六条云厂自研 ASIC 线，即便在芯片层绕开 NVIDIA，在网络层大概率仍在给它付钱。**
2. **★ NVLink Fusion 是一个"开放但必须买我一件东西"的设计**，三条限制：① 每个部署**必须至少包含一个 NVIDIA 产品** ② 第三方 CPU 与第三方加速器**二选一**，不能都用 ③ **负责启动和配置链接的软件层仍由 NVIDIA 控制**，NVSwitch 连接需特殊许可、NUMA/原子操作需额外批准；8 家伙伴中只有 CPU 开发者（Marvell、Fujitsu）拿到软硬全权。→ **DigiTimes：NVLink 不是开放标准，Fusion 是一场精心策划的、以降低 UALink 吸引力为目标的努力。**
3. **★ 与 B2 的正面冲突：AWS Trainium4 通过 UCIe 桥接接入 NVLink 6，并集成进 NVIDIA 的 MGX 机架架构**；给 AWS 设计这颗芯片的 **Marvell 拿了 NVIDIA $20 亿投资**（2026-03-31）；另 **MediaTek $35 亿可转债**、**Lumentum + Coherent 各 $20 亿**。→ **这不是"ASIC 替代 GPU"，而是"ASIC 在 NVIDIA 的机架里做增量"。**
4. **★ 真正绕开 scale-up 护城河的现阶段不是 UALink，是 Google 的 OCS。** Ironwood superpod **9,216 颗 TPU 经 OCS 构成 3D Torus**，ICI 9.6 Tbps、1.77 PB HBM 池、42.5 EF FP8；Apollo OCS **吞吐 +30%、功耗 −40%、波特率无关**；Google 已在 TPU v5p 全面切换、**2026 计划 26 个超算集群 all-in**；**工信部 2026-04-02 已明确推动全光交换**。
5. **★ UALink 的规格已追平（AMD Helios 72× MI400 = 260 TB/s，与 Vera Rubin NVL72 聚合带宽打平），但供应链站到了对面**：第一款 UALink 交换机来自 **Marvell**（2026 末–2027 初），而 Marvell 正是 NVLink Fusion 的被投资方。**且 Marvell 的 UALink 交换机与 CXL 交换机（Structera S 30260，260-lane CXL 3.0，4 TB/s）来自同一笔 XConn 收购——UALink 与 CXL 在 Marvell 身上交汇，而 CXL 是 B8 判定的"绕开 NIXL 的唯一路径"。**
6. **★ "光进铜退"是被市场误造的叙事。黄仁勋 GTC 2026 亲自纠正**："我们需要更多铜缆、更多光模块、更多 CPO 产能"；NVIDIA 网络 SVP：铜无源、零功耗、无有源器件可失效，**只要距离允许就用铜**。分界线是**域大小**：NVL72/144 用铜，**NVL1152 跨机架才转 CPO**。**机架内铜主导至少到 2027，光替代等 2028 Feynman。**
7. **物理边界**：200 Gbps/lane 下无源铜 reach **约 1 米**；NVLink 6 定义 400G SerDes/lane → 铜限 <1 米。铜每比特比光便宜 **5–10 倍**；GB200 NVL72 机架内约 **2 英里**铜缆（另源：约 5,000 根、连接器用量万级）。CPO 让接口功耗 **~30W → ~9W**。
8. **★ 三道非资本可解的门槛（与 B4 的 GOES 同构）**：① **224G+ 连接器缺口 75%**（有效合格产能仅匹配 <25% 需求），安费诺 book-to-bill >1.2、TE 448G 仍卡在送样、罗森泰发泡设备一机难求、北美要求"中国+1"双基地 ② **1.6T 光模块需求 1,500–2,000 万只 vs 有效产能 1,000–1,200 万只**，200G EML 由 Coherent/Lumentum/DSBJ 寡头控制、缺口贯穿 2026–2027 达 2–3 成 ③ **保偏光纤最快 2028 初才放量 + Disco V 槽切割设备 2027 产能已被订完 + InP 衬底三家集中**。
9. **★ CPO 四个口径差 6–300 倍，绝对不可比**：TrendForce 0.5%→35% 渗透率／Nomura 3–5%／摩根士丹利 23k→59k→200k **台**／国内 40 万→1,800 万 **只**。**唯一不受口径争议影响的数字：封测良率当前仅约 20%，2028 才到 50%。** 且 **CPO 交换机要与 AI 加速器抢同一批 2.5D/3D 封装产能**（→ B3 新增需求方）。
10. **网络已独立成业务线（SEC 口径确认）**：NVIDIA FY2026 网络 **$313.76 亿（+141.5%）** vs 算力 +58.9%，占 DC **11.3%→16.2%**；FY2027 Q1 单季 **$148 亿（+199%）**，年化 run rate 约 **$600 亿**。（⚠ 与 B1 的"~12%→~20%"冲突，待核。）NVIDIA 数据中心以太网份额**两年 <4%→21.5% 成第一**；Dell'Oro：AI 后端以太网 2026 Q1 翻倍以上、占 AI 集群交换机约 **2/3**；**Cisco 的 N9100 用的是 NVIDIA Spectrum-X 芯片**。
11. **★ 与 B8 的经济闭环（两边都没单独说出来的结论）：KV 传输有三条路，成本差 1–2 个数量级。** ① 机架内铜（几乎免费）② 跨机架光模块 RDMA（1.6T **$1,200/只**）③ **存储层 NVMe-oF/CXL——Xinnor 实测远端与本地性能完全相同（均 1.52×），"共享不花代价"**。→ **"KV 走网络还是走存储"是纯成本决策，没有性能损失。B8 的"传输层咽喉"因此存在一条绕行路。** 而 DeepSeek 生产实测 **56.3% 输入 token 命中盘上 KV**，说明这条路已被大规模使用。
12. **推论（本文件提出，需旁证）**：NVIDIA 2026-08-04 开放 cuFile API 与存储栈（Google/Intel/Meta 为初始维护者），**动机可能是防止 KV 走存储时脱离自己的栈**。
13. **与 B6 完全咬合**：**Groq LPU 不走 NVLink Fusion**，通过以太网背板（**Oberon ETL256**）连 Vera Rubin，**由 Dynamo 软件编排**——B6 的"推理专用硅永远当不了主机，只能当协处理器"在连接方式上得到印证。
14. **中国在这一层占统治地位（与芯片制造完全相反）**：800G/1.6T 合计份额 **65–70%**、全球 Top10 占 **7 席**、中际旭创约 **27%**；但**上游 DSP（Broadcom/Marvell）、激光器（Lumentum/Coherent/Sumitomo）、InP 衬底（日系）仍是别人的**。FCC 草案三个限定（只管新型号／仍是草案／只管美国实体直接进口）+ **致命模糊点 = 原产地判定口径**；中国已提前对冲（中际旭创 2026 Q1 海外产能出货占比 **84.87%**，泰国产能承接 90%+ 北美订单）。
15. **→ B7 在这一层的命题应反转**：不是"国产能否替代"，而是"**美国能否脱钩**"，且真正的缺口在**上游 DSP / 激光器 / InP 衬底**。中国可能走与美国不同的光路线（华为 OPEN NPO MSA + 工信部全光交换 → 与 Google OCS 同构，而非 NVIDIA/Broadcom 的 CPO）。
